Cache Warmer Pro Documentation

Sitemap-based CDN cache warming after deploys. $9/mo.

Overview

Cache Warmer Pro automatically warms CDN caches after deployments by crawling your sitemap and issuing purge/warm requests to supported CDNs. It eliminates cold-cache latency spikes post-deploy by proactively fetching critical pages before end users hit them.

Core capabilities:

  • Sitemap Parsing: Reads standard XML sitemaps (including nested indexes) to discover URLs.
  • Multi-CDN support: Native integration with Cloudflare, Fastly, Akamai, and Amazon CloudFront.
  • Concurrency control: Configurable parallel requests to avoid origin overload.
  • Exponential backoff: Automatic retry with jitter on 429/5xx responses.
  • Cache header detection: Validates cache-status, x-cache, and provider-specific headers to confirm warm hits.
  • API-first design: Trigger warmups programmatically via REST API or webhook.

Configuration

All settings are defined in a YAML config file or passed as environment variables.

Sitemap URL

Specify one or more sitemap URLs. Nested sitemap indexes are resolved automatically.

sitemap_url: https://example.com/sitemap.xml
# Or multiple:
sitemap_urls:
  - https://example.com/sitemap-pages.xml
  - https://example.com/sitemap-posts.xml

Concurrency

Controls how many URLs are warmed in parallel. Default: 5. Lower values reduce origin load; higher values speed up warmup for large sitemaps.

concurrency: 10

Note: Exceeding your origin’s rate limits may trigger 429s. The backoff system handles retries, but sustained overloads will delay completion.

Backoff

Configures retry behavior for failed requests:

backoff:
  max_retries: 3        # Max attempts per URL (default: 3)
  base_delay_ms: 1000   # Initial delay before first retry (default: 1000)
  multiplier: 2.0       # Delay multiplier per retry (default: 2.0)
  max_delay_ms: 30000   # Cap on retry delay (default: 30000)

Delays include ±20% jitter to prevent thundering herd effects.

Cache Header Detection

Cache Warmer Pro inspects response headers to verify whether a URL was served from cache or fetched from origin. Supported headers:

  • cache-status: hit (generic)
  • x-cache: HIT (CloudFront, Fastly)
  • cf-cache-status: HIT (Cloudflare)
  • x-akamai-cache-status: hit (Akamai)

If no recognized header is present, the tool logs a warning and assumes a miss. Custom header patterns can be added via cache_hit_headers in config:

cache_hit_headers:
  - "x-custom-cache: cached"
  - "x-edge-status: hit"

API Reference

POST /api/cache-warmup

Trigger a cache warmup job programmatically.

Request:

POST /api/cache-warmup
Authorization: Bearer ewr_...
Content-Type: application/json

{
  "sitemap_url": "https://example.com/sitemap.xml",
  "cdn": "cloudflare",
  "concurrency": 5,
  "callback_url": "https://your-app.com/webhook/warmup-complete"
}

Response (202 Accepted):

{
  "job_id": "cw_job_abc123",
  "status": "queued",
  "estimated_duration_s": 120
}

Status Check:
GET /api/cache-warmup/{job_id} returns current progress, hit/miss counts, and any errors.

Webhook Payload (on completion):

{
  "job_id": "cw_job_abc123",
  "status": "completed",
  "urls_processed": 142,
  "cache_hits": 138,
  "errors": [
    {"url": "https://example.com/broken", "error": "404 Not Found"}
  ]
}

Troubleshooting

Common Issues

  • Sitemap parse errors: Ensure sitemap is valid XML and accessible. Use curl -I <sitemap_url> to verify HTTP 200 and Content-Type: application/xml.
  • CDN auth failures: Verify credentials have purge/warm permissions. For CloudFront, ensure IAM policy includes cloudfront:CreateInvalidation.
  • High miss rates: Origin may be returning no-store or private cache directives. Check Cache-Control headers on affected URLs.
  • Timeouts on large sitemaps: Increase concurrency or split into multiple jobs. Monitor origin load during warmup.
  • Webhook not firing: Confirm callback_url is publicly reachable and accepts POST with JSON body. Timeouts >10s are treated as failures.

Debug Mode

Enable verbose logging with --debug flag or LOG_LEVEL=debug env var. Outputs full request/response headers, retry attempts, and header detection logic.
