Overview

DNS Firewall intercepts DNS queries at the resolver level to block malware, phishing, command-and-control traffic, and unwanted content before connections are established. Deploy across networks, endpoints, or cloud infrastructure with centralized policy management and real-time analytics.

  • Block known malicious domains via threat intelligence feeds
  • Custom allow/block lists per network or endpoint group
  • Category-based filtering (ads, trackers, adult, gambling)
  • DNS-over-HTTPS (DoH) and DNS-over-TLS (DoT) support
  • Real-time query logging and forensic search
  • REST API for policy automation and SIEM integration

Setup

Configuring DNS Resolver

# Point clients to DNS Firewall resolver
dns-firewall config --resolver-ip 203.0.113.10

# Enable DoH for encrypted queries
dns-firewall config --doh-endpoint https://dns.edgeiqlabs.com/dns-query

# Add internal network
dns-firewall network add --name "HQ Office" --cidr 10.0.0.0/8

# List configured networks
dns-firewall network list

Policy Configuration

# Apply default threat blocklist
dns-firewall policy apply --default-threats

# Add custom blocklist
dns-firewall policy block --domain badsite.example.com

# Allow specific domain (override blocklist)
dns-firewall policy allow --domain internal.example.com

# Enable category filtering
dns-firewall policy category --block ads,trackers,malware

# Test policy against a query
dns-firewall test-query malware.example.com
Policies are evaluated in order: explicit allows override blocks, which override category filters. Default threat lists update hourly from curated intelligence feeds.

Troubleshooting

Common Issues

Legitimate site blocked: Check policy with dns-firewall test-query example.com. If incorrectly categorized, add an explicit allow rule with dns-firewall policy allow --domain example.com. Submit false positives via dashboard for feed correction.

Queries not being filtered: Verify client DNS settings point to firewall resolver. Use dns-firewall diagnose --client 10.0.1.45 to check connectivity, policy assignment, and bypass status.

Logs missing entries: Confirm --log-level includes desired query types. Check disk space and retention settings. For high-volume networks, enable sampling with --log-sample-rate 10 to reduce storage.

Slow DNS resolution: Review upstream resolver latency with dns-firewall benchmark. Enable local caching with --cache-ttl 300. Consider deploying regional resolvers for distributed networks.

DoH/DoT connection failures: Verify TLS certificates are valid and trusted. Check firewall rules allow outbound port 443 (DoH) or 853 (DoT). Test with dns-firewall test-doh to isolate protocol issues.
