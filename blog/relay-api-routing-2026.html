Stop Rewriting API Routing Every Time You Add a Service

First service is easy. By service seven you are spending more time managing how things talk to each other than building the things themselves.

First service is easy. Direct connection, simple auth, done.

Third service is annoying. Now you have three different auth flows, rate limits scattered across config files, and no idea which service is calling which.

By service seven you are spending more time managing how things talk to each other than building the things themselves.

Relay is the routing layer we built because we got tired of solving this problem from scratch every time.

What It Handles

Centralized auth. One place to validate tokens, check scopes, reject bad requests before they hit your services. Your individual APIs stop caring about authentication entirely. They just receive verified requests.

Rate limiting across all services, not per-service. If someone hammers your search endpoint and your user endpoint simultaneously, Relay sees the total load and throttles accordingly. Individual services only see their own traffic and miss the bigger picture.

Request transformation. Service A returns XML. Service B needs JSON. Instead of building adapters everywhere, Relay transforms in transit. Header injection, field mapping, response reshaping. All configured in one place.

Multi-service orchestration. When a single client request needs to hit three services and combine the results, Relay coordinates it. Parallel calls when possible, sequential when dependencies exist. Your frontend makes one request instead of five.

Why Not Just Use Kong or AWS API Gateway

You can. If you have the budget and the team to configure them. Kong requires a dedicated operator once you get past basic routing. AWS API Gateway locks you into their ecosystem and charges per million requests in ways that surprise you at the end of the month.

Relay is built for teams running 3 to 20 services who need routing infrastructure without hiring an infrastructure person. It runs alongside your existing stack. Does not replace your services. Just sits in front and handles the plumbing.

The Point

Your developers should build features. Not debug why service C stopped receiving headers after service B updated its auth middleware.

Relay removes that category of problems entirely.

Pricing and setup details are on the site. The architecture docs explain how it fits into existing deployments without downtime.
