Overview

Webhook Integrations allow EdgeIQ findings to be pushed automatically to external systems when new vulnerabilities are detected, severity changes occur, or monitoring thresholds are breached. Includes HMAC-SHA256 signature verification, exponential backoff retry logic, and customizable payload templates for seamless integration with existing workflows.

  • Native integrations for Jira, ServiceNow, and Slack
  • Generic webhook support for custom endpoints
  • HMAC-SHA256 signature verification on every payload
  • Automatic retry with exponential backoff (up to 8 attempts)
  • Customizable payload schemas per destination
  • Delivery logs and failure alerts via dashboard

Setup

Configuring a Webhook Endpoint

# Via CLI
edgeiq webhooks add \
  --name "Production Jira" \
  --url https://your-org.atlassian.net/rest/api/3/issue \
  --secret whsec_your_signing_secret \
  --template jira

# Via API
curl -X POST https://api.edgeiqlabs.com/v1/webhooks \
  -H "Authorization: Bearer $EDGEIQ_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Security Slack Channel",
    "url": "https://hooks.slack.com/services/T00/B00/xxx",
    "template": "slack",
    "events": ["finding.created", "severity.changed"]
  }'
Store your signing secret securely. EdgeIQ never displays the full secret after creation. Use edgeiq webhooks rotate-secret <id> to regenerate if compromised.

Payload Schema

All webhook payloads follow a consistent envelope format. Fields vary slightly by template but maintain this core structure:

{
  "event": "finding.created",
  "timestamp": "2026-11-06T14:32:00Z",
  "webhook_id": "wh_abc123",
  "data": {
    "finding_id": "find_xyz789",
    "asset": "192.168.1.10",
    "port": 443,
    "service": "nginx/1.24.0",
    "severity": "high",
    "title": "TLS 1.0 Enabled",
    "description": "Server supports deprecated TLS 1.0 protocol...",
    "recommendation": "Disable TLS 1.0 and 1.1 in nginx config",
    "cve_ids": ["CVE-2011-3389"],
    "scan_id": "scan_def456"
  }
}
FieldTypeDescription
eventstringTrigger type: finding.created, severity.changed, monitor.alert
timestampISO 8601UTC timestamp of the event
webhook_idstringUnique identifier for this webhook configuration
dataobjectFinding details (schema varies by template)

Signature Verification

Every webhook request includes an X-EdgeIQ-Signature header containing an HMAC-SHA256 signature of the raw request body. Always verify this signature before processing payloads to prevent spoofing.

# Python verification example
import hmac, hashlib

def verify_signature(payload_body, signature_header, secret):
    expected = hmac.new(
        secret.encode(),
        payload_body,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, signature_header)

# Usage
if not verify_signature(request.body, request.headers['X-EdgeIQ-Signature'], WEBHOOK_SECRET):
    raise ValueError("Invalid signature")
Use constant-time comparison (hmac.compare_digest) to prevent timing attacks. Never use == for signature validation.

Retry Logic

Failed deliveries are retried automatically with exponential backoff:

1Immediate0s
230 seconds30s

415 minutes~17.5 min
51 hour~1.3 hr
64 hours~5.3 hr
712 hours~17.3 hr
824 hours~41.3 hr

After 8 failed attempts, the webhook is marked as failing and an alert is sent to your account email. Retries trigger on HTTP 5xx errors, timeouts (>10s), and connection failures. HTTP 4xx responses are treated as permanent failures and not retried.

Supported Destinations

Jira

Automatically creates issues in specified projects with severity-based priority mapping. Supports Jira Cloud and Data Center.

edgeiq webhooks add \
  --name "Jira Security Queue" \
  --url https://your-org.atlassian.net/rest/api/3/issue \
  --secret whsec_jira_secret \
  --template jira \
  --config '{"project_key":"SEC","issue_type":"Bug","priority_map":{"critical":"Highest","high":"High"}}'

ServiceNow

Creates incidents or security tickets via ServiceNow REST API. Maps severity to urgency/impact fields.

edgeiq webhooks add \
  --name "ServiceNow SecOps" \
  --url https://instance.service-now.com/api/now/table/incident \
  --secret whsec_snow_secret \
  --template servicenow \
  --config '{"assignment_group":"security-ops","urgency_field":"severity"}'

Slack

Posts formatted messages to channels with color-coded severity indicators and action buttons.

edgeiq webhooks add \
  --name "#security-alerts" \
  --url https://hooks.slack.com/services/T00/B00/xxx \
  --template slack \
  --config '{"channel":"#security-alerts","mention_on_critical":"@security-team"}'

Generic HTTP

Send raw JSON payloads to any HTTPS endpoint. Useful for custom SOAR playbooks, internal dashboards, or SIEM ingestion.

edgeiq webhooks add \
  --name "Internal SIEM" \
  --url https://siem.internal.corp/api/v1/events \
  --secret whsec_custom_secret \
  --template generic \
  --headers '{"X-API-Key":"${env:SIEM_KEY}"}'

Troubleshooting

Common Issues

Signature verification fails: Ensure you're hashing the raw request body exactly as received (no re-encoding). Verify the secret matches what's stored in EdgeIQ dashboard. Check for trailing whitespace in copied secrets.

Webhook returns 401/403: For Jira/ServiceNow, verify API tokens have write permissions. For Slack, ensure the app has chat:write scope and is added to the target channel.

Delays in notification: Check delivery logs at /v1/webhooks/{id}/deliveries. High latency may indicate endpoint throttling. Consider increasing timeout threshold via support request.

Duplicate tickets created: Implement idempotency using finding_id from payload. Most destinations support deduplication keys in their APIs.

Payload missing fields: Verify template matches destination. Generic template sends full schema; platform-specific templates may omit redundant fields. Use --template generic to debug field availability.
