Repo Scanner Pro Documentation

Overview

Repo Scanner Pro is an automated security auditing tool that scans GitHub repositories for common misconfigurations and exposed secrets. It performs static analysis on repository structure, configuration files, and dependency manifests to identify security risks.

Getting Started

Prerequisites

  • GitHub repository URL (public or private)
  • For private repos: Valid GitHub Personal Access Token with repo scope
  • Active EdgeIQ Labs account

Installation

npm install -g @edgeiq/repo-scanner-pro

Authentication

rsp auth login --token YOUR_EDGEIQ_API_KEY

Free Tier Checks

The free tier includes 7 automated checks on public repositories only:

  1. Exposed Secrets: Scans for hardcoded API keys, tokens, and passwords in source code
  2. .env File Detection: Identifies committed environment files containing sensitive variables
  3. .gitignore Validation: Verifies presence and completeness of .gitignore patterns
  4. Supabase RLS Policy Check: Detects tables without Row Level Security policies enabled
  5. Default Configuration Files: Flags production configs with debug mode enabled
  6. Public S3 Bucket References: Identifies hardcoded public bucket URLs in code
  7. Dependency License Compliance: Basic check for known restrictive licenses in top-level dependencies

Pro Tier Features ($9/mo)

  • Private Repository Support: Full scanning capability for private GitHub repos via authenticated access
  • Deep Dependency Audit: Transitive dependency analysis for known CVEs and vulnerable versions
  • Custom Rule Sets: Define organization-specific security policies and violation thresholds
  • Historical Scan Tracking: Compare results across commits and branches over time
  • Webhook Integration: Automatic re-scanning on push events and PR creation
  • Export Formats: JSON, SARIF, and CSV output for CI/CD pipeline integration

API Reference

Endpoint

POST /api/repo-scanner

Request Body

Field Type Required Description
url string Yes Full GitHub repository URL (e.g., https://github.com/org/repo)
branch string No Target branch to scan (default: main/master)
depth integer No Commit history depth for secret detection (default: 50)
include_dependencies boolean No Enable transitive dependency audit (Pro tier only)

Example Request

curl -X POST https://edgeiqlabs.com/api/repo-scanner \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://github.com/example/my-app", "branch": "develop"}'

Response Schema

{
  "scan_id": "uuid-v4",
  "repository": "example/my-app",
  "grade": "B",
  "score": 72,
  "findings": [
    {

      "check": "exposed_secrets",

    }
  ],
  "timestamp": "2026-11-06T10:30:00Z"

Interpreting Results

Grading Scale

  • A (90-100): No critical or high-severity findings
  • B (80-89): Minor issues present, no immediate risk
  • C (70-79): Medium-severity findings requiring attention
  • D (60-69): High-severity issues detected
  • F (<60): Critical vulnerabilities or multiple high-severity findings

Scoring Logic

Base score starts at 100. Deductions are applied per finding:

  • Critical severity: -30 points
  • High severity: -15 points
  • Medium severity: -8 points
  • Low severity: -3 points

Score floors at 0. Multiple findings of the same type stack cumulatively.

Troubleshooting

Error: Repository not accessible
Verify the repository URL is correct. For private repos, ensure your GitHub token has repo scope and hasn't expired. Re-authenticate with rsp auth refresh.
Error: Rate limit exceeded
GitHub API rate limits apply. Free tier allows 10 scans/hour. Pro tier allows 100 scans/hour. Wait before retrying or upgrade your plan.
Scan completes but returns no findings
This indicates a clean repository. Verify you're scanning the correct branch. Some checks require specific file types to be present (e.g., Supabase RLS check requires migration files).
CLI hangs during authentication
Check network connectivity and firewall rules. Ensure api.edgeiqlabs.com:443 is whitelisted. Try rsp auth login --verbose for detailed logs.
False positive in secret detection
Add false positives to .rspignore in repo root using regex patterns. Example: ^TEST_API_KEY_.*$
