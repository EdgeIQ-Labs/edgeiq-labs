SSH Key Setup

Password authentication is disabled by default. Add your SSH public key during provisioning or via the dashboard after deployment.

# Generate an Ed25519 key pair (recommended)
ssh-keygen -t ed25519 -C "your_email@example.com"

# Copy your public key
cat ~/.ssh/id_ed25519.pub

# Paste into the EdgeIQ dashboard under Server > SSH Keys
# Or add via API at provisioning time
RSA keys are supported but Ed25519 is recommended for performance and security. Password auth can be re-enabled in /etc/ssh/sshd_config but is strongly discouraged.

Server Hardening

All EdgeIQ VPS instances ship with a CIS Benchmark-aligned hardening profile applied automatically. This reduces attack surface without requiring manual configuration.

  • Firewall enabled (UFW/nftables) with only SSH (22) open by default
  • Root login disabled; sudo user created at provisioning
  • Fail2ban configured for SSH brute-force protection
  • Automatic security updates enabled (unattended-upgrades)
  • Kernel hardening via sysctl (ASLR, SYN cookies, ICMP rate limiting)
  • Auditd logging enabled for privilege escalation events
# View current hardening status
edgeiq-hardening status

# Re-apply hardening profile after custom changes
sudo edgeiq-hardening apply --profile cis-l1

Wazuh Integration

Wazuh SIEM provides real-time intrusion detection, log analysis, file integrity monitoring, and compliance reporting. The Wazuh agent can be deployed during provisioning or installed post-deployment.

# One-click install during provisioning (dashboard or API)
# Or install manually post-deployment:

  --manager-ip wazuh-mgr.edgeiqlabs.com \
  --agent-name $(hostname)

# Verify agent connection
sudo /var/ossec/bin/agent_control -l

Troubleshooting

Common Issues

Cannot SSH into server: Verify your SSH key was added during provisioning. Check that port 22 isn't blocked by your local firewall. Use the web console in the EdgeIQ dashboard as a fallback.

Backup restore fails: Ensure the target snapshot exists with edgeiq-backup list. Restores require the server to be powered off first. Check available backup storage quota for your plan tier.

Wazuh agent shows disconnected: Verify outbound connectivity to wazuh-mgr.edgeiqlabs.com:1514. Check /var/ossec/logs/ossec.log for registration errors. Re-register with sudo /var/ossec/bin/agent-auth -m wazuh-mgr.edgeiqlabs.com.

High latency during DDoS event: Mitigation activates within seconds. If latency persists beyond 5 minutes, check the DDoS events dashboard for ongoing attack patterns. Contact support if mitigation appears ineffective.

Server won't boot after hardening: Boot into rescue mode from the dashboard, mount the filesystem, and revert /etc/ssh/sshd_config or sysctl changes. Run edgeiq-hardening rollback from rescue shell.
