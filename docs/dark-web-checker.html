Dark Web Credential Checker

Documentation · EdgeIQ Labs

Overview

The EdgeIQ Labs Dark Web Credential Checker monitors known breach databases, paste sites, and dark web marketplaces for exposed credentials associated with your organization. When a match is found, the system generates an alert containing the breach source, exposure date, and affected credential hash.

This tool does not store plaintext passwords. All monitored credentials are stored as salted SHA-256 hashes. Breach data is queried via k-anonymity to prevent credential leakage during lookups.

Setup

  1. Navigate to Settings → API Keys and generate a new key with darkweb:read scope.
  2. Store the key securely; it will not be displayed again.
  3. Configure your organization domain under Settings → Organization. This domain is used to auto-suggest monitored email patterns.
  4. Verify ownership of each monitored domain via DNS TXT record or HTTP file challenge before enabling alerts.

Monitored Credentials Configuration

Credentials can be added individually or via bulk import. Supported formats:

  • Email addresses: Monitors all breaches containing the exact address.
  • Domain patterns: *@example.com monitors all current and future addresses at that domain.
  • Username lists: CSV upload (max 10,000 rows). Must include header row.

To add credentials manually:

POST /api/v1/monitored-credentials
{
  "type": "email",
  "value": "admin@example.com",
  "tags": ["it-admin", "critical"]
}

All values are hashed server-side before storage. The API rejects plaintext passwords; only identifiers (emails, usernames) are accepted.

Alert Channels

Configure delivery methods under Settings → Alert Channels:

  • Email: Default channel. Supports digest mode (daily/weekly summary).
  • Webhook: POST JSON payload to your endpoint. Includes HMAC-SHA256 signature in X-EdgeIQ-Signature header.
  • Slack: OAuth integration. Posts to selected channel with interactive buttons for acknowledge/dismiss.
  • PagerDuty: Creates incident for critical-severity exposures only.

Each channel supports severity filtering (Critical, High, Medium, Low) and tag-based routing.

API Reference

Authentication

All requests require Authorization: Bearer <api_key> header. Rate limit: 100 requests/minute per key.

Endpoints

# Run one-time check
POST /api/v1/check
Body: { "identifiers": ["user@example.com"] }
Response: { "matches": [...], "checked_at": "2026-11-06T12:00:00Z" }

# List monitored credentials
GET /api/v1/monitored-credentials?page=1&limit=50
Response: { "data": [...], "total": 142 }

# Add credential to monitoring
POST /api/v1/monitored-credentials
Body: { "type": "domain_pattern", "value": "*@example.com" }

# Delete monitored credential
DELETE /api/v1/monitored-credentials/{id}

# Get alert history
GET /api/v1/alerts?since=2026-10-01&severity=critical
Response: { "alerts": [...] }

Interpreting Results

Each match includes:

  • Breach Source: Name or hash of the originating dataset (e.g., Collection #5, PasteBin_2026-09).
  • Exposure Date: Earliest known appearance in monitored sources.
  • Data Classes: Types of compromised data (password, email, phone, SSN partial).
  • Severity: Calculated based on data sensitivity and recency. Critical = password + PII within 90 days.
  • Remediation Status: Tracks whether password reset was confirmed via integrated IdP or manual acknowledgment.

False positives occur when breached emails match inactive accounts. Use tags to filter legacy systems from active alerting.

Troubleshooting

  • No results for known breach: Verify domain ownership is complete. Unverified domains return empty result sets by design.
  • Webhook failures: Ensure endpoint returns 2xx within 10 seconds. Failed deliveries retry 3x with exponential backoff. Check Settings → Alert Channels → Logs for error details.
  • Rate limit exceeded: Implement client-side throttling. Batch identifier checks using array payloads instead of individual requests.
  • Missing Slack notifications: Re-authorize OAuth token if workspace permissions changed. Test via Send Test Alert button.
