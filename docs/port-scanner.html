Overview

Port Scanner Pro provides comprehensive TCP/UDP port scanning with automatic service banner grabbing, high-risk port identification, and scheduled continuous monitoring. Designed for security professionals, sysadmins, and DevOps teams who need reliable network visibility without complex configuration.

  • Scan single hosts, CIDR ranges, or custom port lists
  • Automatic service banner detection (SSH, HTTP, FTP, SMTP, etc.)
  • Built-in high-risk port database with severity tagging
  • Continuous monitoring with alerting via webhook/email
  • REST API for integration into CI/CD and SOAR workflows

Quick Start

# Install via pip
pip install edgeiq-port-scanner

# Run a basic scan
port-scanner scan 192.168.1.1

# Scan a range with banner detection
port-scanner scan 10.0.0.0/24 --banners --top-ports 1000

# Start continuous monitoring
port-scanner monitor add 192.168.1.1 --interval 3600 --alert-webhook https://hooks.example.com/alert

Service Banner Detection

When --banners is enabled, Port Scanner Pro connects to open ports and captures the initial service response. Supported protocols include SSH, HTTP/HTTPS, FTP, SMTP, POP3, IMAP, MySQL, PostgreSQL, Redis, and MongoDB.

$ port-scanner scan 192.168.1.1 --banners
PORT     STATE  SERVICE         BANNER
22/tcp   open   ssh             OpenSSH_8.9p1 Ubuntu-3ubuntu0.6
80/tcp   open   http            nginx/1.24.0
443/tcp  open   ssl/http        nginx/1.24.0
3306/tcp open   mysql           MySQL 8.0.35
8080/tcp open   http-proxy      Apache Tomcat/9.0.82
Banner detection adds ~2-5 seconds per open port. Use --banner-timeout 3 to limit wait time on unresponsive services.

Continuous Monitoring Setup

Schedule recurring scans to detect new open ports, service changes, or high-risk exposures over time.

# Add a monitored target (scan every hour)
port-scanner monitor add 192.168.1.0/24 --interval 3600 --banners

# Configure webhook alerts
port-scanner monitor config --alert-webhook https://hooks.slack.com/services/xxx

# Configure email alerts
port-scanner monitor config --alert-email admin@example.com

# List active monitors
port-scanner monitor list

# View change history
port-scanner monitor history 192.168.1.1 --last 30d
Monitors persist across restarts. State is stored in ~/.edgeiq/monitors.db. Use monitor remove <target> to stop tracking.

Troubleshooting

Common Issues

No ports detected on known-active host: Verify firewall rules aren't blocking ICMP or SYN packets. Try --scan-type connect for TCP connect fallback if SYN scanning is filtered.

Banner detection hangs: Reduce timeout with --banner-timeout 2. Some services delay responses to deter scanners.

Monitor not alerting: Test webhook with port-scanner monitor test-alert. Check ~/.edgeiq/logs/monitor.log for delivery errors.

Permission denied on Linux/macOS: SYN scanning requires root/CAP_NET_RAW. Run with sudo or use --scan-type connect for unprivileged operation.

False positives in high-risk list: Override with --exclude-risk-ports 3306,5432 if those services are intentionally exposed and hardened.
