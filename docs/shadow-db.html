Overview

Shadow DB provides comprehensive database security scanning for modern infrastructure. It identifies misconfigurations, default credentials, missing patches, and SQL injection vulnerabilities before attackers exploit them. Designed for DevOps teams, DBAs, and security engineers managing multi-database environments.

  • Supports MySQL, PostgreSQL, MongoDB, and Redis
  • Detects weak/default credentials via safe authentication testing
  • Identifies unpatched CVEs with version fingerprinting
  • Finds SQL injection vectors in stored procedures and views
  • Generates prioritized remediation reports with fix commands
  • REST API for CI/CD integration and automated compliance checks

Read-Only User Creation

For safety, create a dedicated read-only user for scanning. Never use admin/root credentials.

-- MySQL
CREATE USER 'shadow_scanner'@'%' IDENTIFIED BY 'strong_password';
GRANT SELECT, SHOW VIEW ON *.* TO 'shadow_scanner'@'%';
FLUSH PRIVILEGES;

-- PostgreSQL
CREATE ROLE shadow_scanner WITH LOGIN PASSWORD 'strong_password';
GRANT CONNECT ON DATABASE prod TO shadow_scanner;
\c prod
GRANT USAGE ON SCHEMA public TO shadow_scanner;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO shadow_scanner;

-- MongoDB (mongosh)
use admin
db.createUser({
  user: "shadow_scanner",
  pwd: "strong_password",
  roles: [{ role: "readAnyDatabase", db: "admin" }]
});

-- Redis (redis.conf or ACL)
ACL SETUSER shadow_scanner on >strong_password ~* +@read +@connection
Shadow DB never writes to your database. All scans are read-only. The scanner uses metadata queries and safe authentication probes only.

Scan Configuration

CLI Usage

# Install via pip
pip install edgeiq-shadow-db

# Scan a single database
shadow-db scan mysql://reader:pass@db.example.com:3306/app

# Scan multiple targets from file
shadow-db scan --targets-file databases.txt --output report.json

# Run specific check categories
shadow-db scan postgresql://u:p@host/db --checks credentials,cve,sqli

# Schedule continuous monitoring
shadow-db monitor add mysql://reader:pass@db.example.com:3306/app --interval 86400

Configuration File

Create ~/.shadow-db/config.yaml for persistent settings:

scanning:
  timeout: 30
  max_connections: 5
  retry_attempts: 3

checks:
  credentials: true
  cve: true
  sqli: true
  config_misconfigs: true

alerting:
  webhook_url: https://hooks.slack.com/services/xxx
  email: security@example.com
  severity_threshold: high

Remediation Steps

Each finding includes actionable fix commands tailored to your database version:

# Finding: WEAK_CREDENTIAL_001 - MySQL root has empty password
# Severity: CRITICAL
# Fix:
ALTER USER 'root'@'localhost' IDENTIFIED BY 'new_strong_password';
DELETE FROM mysql.user WHERE User='root' AND Host NOT IN ('localhost', '127.0.0.1', '::1');
FLUSH PRIVILEGES;

# Finding: EXPOSED_DB_003 - MongoDB bound to 0.0.0.0
# Severity: CRITICAL
# Fix: Edit /etc/mongod.conf
net:
  bindIp: 127.0.0.1
security:
  authorization: enabled
# Then restart: sudo systemctl restart mongod

# Finding: UNPATCHED_CVE_2021_23214
# Severity: HIGH
# Fix: Upgrade PostgreSQL to 13.5+
sudo apt update && sudo apt install postgresql-13
Always test remediation commands in staging first. Shadow DB provides rollback scripts for every fix.

Troubleshooting

Common Issues

Authentication failed: Verify connection string credentials. Ensure the scanner user has been granted CONNECT and SELECT permissions. Test with native client first (mysql -u shadow_scanner -p).

Connection timeout: Check firewall rules allow inbound traffic on the database port. Verify the database isn't bound to localhost only if scanning remotely. Increase --timeout 60 for slow networks.

Permission denied errors: The scanner user lacks required privileges. Re-run the GRANT statements from Setup. For PostgreSQL, ensure GRANT USAGE ON SCHEMA was executed per-schema.

CVE detection inaccurate: Version fingerprinting may fail on custom builds. Manually verify with SELECT VERSION(); and cross-reference NVD. Submit false positives via shadow-db report-false-positive.

Monitor not alerting: Test webhook with shadow-db monitor test-alert. Check ~/.shadow-db/logs/monitor.log for delivery errors. Verify severity threshold isn't filtering out findings.

Scan hangs on large schema: Reduce scope with --max-tables 100 or exclude schemas with --exclude information_schema,performance_schema.
