Overview

Rate Watch tracks product prices across e-commerce platforms, competitor sites, and marketplaces. Get instant alerts when prices drop below thresholds, competitors adjust pricing, or market trends emerge. Ideal for procurement teams, resellers, and competitive intelligence analysts.

  • Monitor unlimited product URLs across multiple retailers
  • Track price history with visual trend charts
  • Set custom alert thresholds (percentage or absolute)
  • Detect out-of-stock and restock events
  • Instant alerts via email, webhook, Slack, or Discord
  • REST API for integration into procurement and BI workflows

Setup

Adding Products to Monitor

# Add a single product URL
rate-watch add https://example.com/product/123

# Add multiple products from CSV
rate-watch add --file products.csv

# Set price threshold ($50 or 10% drop)
rate-watch config https://example.com/product/123 --threshold 50 --threshold-pct 10

# List monitored products
rate-watch list

Configuring Alert Channels

# Email alerts
rate-watch config --alert-email procurement@example.com

# Webhook (generic)
rate-watch config --alert-webhook https://hooks.example.com/rate-watch

# Slack integration
rate-watch config --slack-webhook https://hooks.slack.com/services/xxx

# Discord integration
rate-watch config --discord-webhook https://discord.com/api/webhooks/xxx

# Test alert delivery
rate-watch test-alert
Multiple alert channels can be configured simultaneously. All channels receive identical payloads for redundancy.

  --interval 1800 \

Troubleshooting

Common Issues

Product not tracking: Verify the URL is accessible and not blocked by bot protection. Use rate-watch check https://example.com/product/123 to run a one-off diagnostic including page fetch, price extraction, and stock status.

Price not detected: The site may use dynamic rendering. Enable --js-render to execute JavaScript before parsing. Check ~/.edgeiq/logs/rate-watch.log for selector mismatches.

Alerts not delivering: Test with rate-watch test-alert. Verify webhook endpoints return HTTP 2xx. Check SMTP credentials for email delivery failures.

Too many false positives: Adjust --threshold-pct to ignore minor fluctuations. Enable --debounce 3 to require 3 consecutive readings before alerting.

Rate limited by retailer: Increase --interval to 7200+ seconds. Rotate user agents with --rotate-ua or configure proxy support via --proxy socks5://localhost:9050.
