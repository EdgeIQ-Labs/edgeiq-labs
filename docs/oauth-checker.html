OAuth Security Checker Pro

Overview

OAuth Security Checker Pro is a comprehensive validation tool designed to identify common misconfigurations and vulnerabilities in OAuth 2.0 and OpenID Connect implementations. It automates critical security checks including redirect URI validation, state token verification, PKCE detection, scope analysis, and token leakage prevention.

This tool helps developers and security teams ensure their OAuth flows are properly configured before deployment, reducing the risk of authorization code interception, CSRF attacks, and privilege escalation.

Quick Start

  1. Install via npm: npm install -g @edgeiq/oauth-checker-pro
  2. Configure your provider endpoints in oauth-config.json
  3. Run the checker: oauth-checker run --config oauth-config.json
  4. Review the generated report at ./oauth-report.html

Test Checklist

Redirect URI Validation

  • Verifies all registered redirect URIs use HTTPS (except localhost for development)
  • Detects open redirect vulnerabilities via query parameter manipulation
  • Validates exact match vs. prefix matching behavior
  • Checks for fragment-based redirects that may leak tokens

State Token Checks

  • Confirms state parameter is present in authorization requests
  • Validates state is cryptographically random (≥128 bits entropy)
  • Verifies state is bound to user session and validated on callback
  • Detects state reuse across multiple authorization flows

PKCE Detection

  • Identifies whether PKCE is supported by the provider
  • Validates code_verifier length (43-128 characters)
  • Checks code_challenge_method is S256 (not plain)
  • Ensures code_verifier is not reused across sessions

Scope Analysis

  • Audits requested scopes against principle of least privilege
  • Flags overly broad scopes (e.g., admin, write_all)
  • Validates scope format matches provider specification
  • Detects scope escalation between auth and token requests

Token Leakage Prevention

  • Scans for tokens in URL fragments, query strings, or logs
  • Validates tokens are transmitted only over TLS
  • Checks for proper token storage (no localStorage/sessionStorage)
  • Verifies refresh token rotation and binding

API Reference

CLI Commands

oauth-checker run --config <path>     # Run full security scan
oauth-checker validate-uri <uri>      # Validate single redirect URI
oauth-checker check-pkce <endpoint>   # Test PKCE support
oauth-checker audit-scopes <config>   # Analyze scope permissions
oauth-checker export --format json    # Export results as JSON

Configuration Options

  • --strict: Fail on warnings (default: false)
  • --timeout: Request timeout in seconds (default: 30)
  • --output: Report output path (default: ./oauth-report.html)
  • --verbose: Enable detailed logging

Common Misconfigurations

  • Wildcard Redirect URIs: Using https://*.example.com/callback allows subdomain takeover attacks.
  • Missing State Parameter: Enables CSRF attacks where attackers link victim accounts to attacker-controlled identities.
  • Plain PKCE Method: Using code_challenge_method=plain exposes the verifier to interception.
  • Overly Broad Scopes: Requesting admin or write_all when only read access is needed violates least privilege.
  • Token in URL: Storing access tokens in URL fragments leaks them via browser history and referrer headers.
  • No Refresh Token Rotation: Reusing refresh tokens enables token theft persistence after revocation.

Troubleshooting

False Positives

If the tool flags a valid configuration as insecure, verify:

  • Your provider's documentation confirms the pattern is safe
  • You're using the correct endpoint version (v1 vs v2)
  • Custom domains are properly registered with the provider

Connection Errors

  • Ensure your network allows outbound HTTPS to the provider's endpoints
  • Check if corporate proxies require certificate whitelisting
  • Verify client credentials have not expired or been revoked

Incomplete Reports

If certain checks are skipped:

  • Confirm the provider supports the feature being tested
  • Check that required configuration fields are present
  • Review verbose logs for specific skip reasons
