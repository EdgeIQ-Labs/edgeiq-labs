Overview

The Screenshot API provides reliable, headless browser-based screenshot capture for web pages, dashboards, reports, and visual regression testing. Built on Chromium with full JavaScript rendering support, it handles SPAs, lazy-loaded content, and complex layouts without configuration.

  • Full-page capture including below-the-fold content
  • Custom viewport dimensions and device presets (mobile, tablet, desktop)
  • Configurable wait times for JS-heavy pages and animations
  • PNG and JPEG output with quality control
  • REST API with simple authentication and predictable rate limits

Setup

API Key

All requests require an API key passed in the X-API-Key header. Generate your key from the EdgeIQ Dashboard.

# Store your key securely
export EDGEIQ_API_KEY="ei_live_xxxxxxxxxxxxxxxxxxxx"

Endpoint

Base URL for all Screenshot API requests:

POST https://api.edgeiqlabs.com/v1/screenshot

Parameters

ParameterTypeRequiredDefaultDescription
urlstringYes—Target URL to capture (must include http/https scheme)
viewport_widthintegerNo1920Browser viewport width in pixels (320–3840)
viewport_heightintegerNo1080Browser viewport height in pixels (320–2160)
devicestringNodesktopDevice preset: desktop, tablet, mobile, or custom. Overrides viewport when not custom.
delay_msintegerNo1000Wait time after page load before capture (0–30000 ms). Use for JS rendering, animations, or lazy-loaded assets.
formatstringNopngOutput format: png or jpeg
qualityintegerNo90JPEG quality (1–100). Ignored for PNG.
full_pagebooleanNotrueCapture entire scrollable page. Set false for viewport-only crop.

Example Request

curl -X POST https://api.edgeiqlabs.com/v1/screenshot \
  -H "X-API-Key: $EDGEIQ_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/dashboard",
    "device": "desktop",
    "delay_ms": 2000,
    "format": "png",
    "full_page": true
  }' \
  --output screenshot.png

Response Format

Successful requests return the image binary directly in the response body with appropriate headers:

HTTP/1.1 200 OK
Content-Type: image/png
Content-Length: 245891
X-Request-ID: req_abc123def456
X-RateLimit-Remaining: 498

[binary image data]

For programmatic handling, you can request JSON metadata instead by adding Accept: application/json:

{
  "request_id": "req_abc123def456",
  "url": "https://example.com/dashboard",
  "format": "png",
  "size_bytes": 245891,
  "dimensions": {"width": 1920, "height": 4832},
  "captured_at": "2026-11-06T14:22:18Z",
  "download_url": "https://cdn.edgeiqlabs.com/screenshots/req_abc123def456.png?expires=1730992938"
}
JSON responses include a signed download_url valid for 1 hour. Binary responses stream directly and are more efficient for automated pipelines.

Troubleshooting

Common Issues

Screenshot appears blank or incomplete: Increase delay_ms to allow JavaScript frameworks (React, Vue, Angular) to hydrate. Try 3000–5000ms for heavy SPAs.

Mobile layout not rendering correctly: Use device: "mobile" instead of manual viewport. Device presets include correct user-agent strings and DPR scaling.

Fonts or images missing: Ensure target site allows hotlinking. Some CDNs block headless browsers; try adding User-Agent override via support ticket for enterprise plans.

Timeouts on internal/private URLs: Screenshot API cannot access localhost, private IPs, or VPN-only resources. Use our self-hosted renderer for intranet targets.

JPEG artifacts or low quality: Increase quality parameter (default 90). For pixel-perfect output, use PNG format.

Rate limit errors during batch processing: Implement queue with backpressure. Pro plan supports 60 req/min burst; space requests evenly using token bucket algorithm.
