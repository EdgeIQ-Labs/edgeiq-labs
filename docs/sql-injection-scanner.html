SQL Injection Scanner Pro Documentation

Overview

SQL Injection Scanner Pro is a precision security testing tool designed to identify SQL injection vulnerabilities in web applications and APIs. It combines four distinct detection methodologies—boolean blind, time-based, UNION SELECT, and error-based—to uncover both obvious and subtle injection points that single-method scanners miss. Beyond vulnerability detection, it verifies parameterized query implementation to confirm remediation effectiveness.

  • Pricing: $39 lifetime license or $19/month subscription.
  • Licensing: Lifetime licenses include all future feature updates; subscriptions provide priority support and early access to beta detection modules.
  • Deployment: Standalone CLI binary (Linux, macOS, Windows) with optional REST API mode for CI/CD integration.
  • Compliance alignment: Findings map to OWASP Top 10 A03:2021 (Injection), CWE-89, and PCI DSS Requirement 6.5.1.

Quick Start

  1. Install: Download the binary for your platform from the dashboard or install via package manager: 
    # Homebrew (macOS/Linux)
brew install edgeiq/tap/sqli-scanner-pro

# Direct download (Linux x86_64)
curl -fsSL https://dl.edgeiqlabs.com/sqli-scanner-pro/latest/linux-amd64.tar.gz | tar xz
sudo mv sqli-scanner-pro /usr/local/bin/
  2. Authenticate: Run sqli-scanner-pro auth login to link your license key or subscription account.
  3. Run a scan: 
    # Basic scan against a single URL
sqli-scanner-pro scan --target "https://app.example.com/search?q=test"

# Full scan with all detection methods
sqli-scanner-pro scan --target "https://app.example.com/api/users" \
  --methods boolean,time,union,error \
  --output report.json
  4. Review results: Output includes vulnerable parameters, injection type, confidence score, and proof-of-concept payloads. JSON output integrates with CI pipelines; HTML reports are generated with --format html.

Detection Methods

SQL Injection Scanner Pro employs four complementary detection strategies. Each method targets different application behaviors and database response patterns.

Boolean Blind Detection

Identifies injection points where the application returns different HTTP responses or page content based on injected boolean conditions. The scanner injects tautologies (' OR '1'='1) and contradictions (' AND '1'='2) to observe behavioral differences without requiring visible error messages or data extraction.

  • Best for: Applications that suppress errors but reflect query logic in rendered content.
  • Confidence threshold: Requires ≥3 consistent differential responses to mark as vulnerable.
  • Limitation: Cannot extract data directly; confirms vulnerability existence only.

Time-Based Detection

Detects blind injection by measuring response latency after injecting database sleep functions (SLEEP(), pg_sleep(), WAITFOR DELAY). A statistically significant delay (default: >5 seconds beyond baseline) indicates successful payload execution.

  • Best for: Fully blind scenarios with no content differentiation or error feedback.
  • Adaptive timing: Baseline latency is sampled per-target before injection; thresholds adjust for high-latency endpoints.
  • False positive mitigation: Retests delayed responses 3x; discards results with >30% variance.

UNION SELECT Detection

Attempts to append UNION SELECT clauses to extract column count, data types, and sample data. The scanner auto-detects column arity through incremental probing and matches injected marker strings in response bodies.

  • Best for: Confirming exploitable injection and assessing data exposure risk.
  • Safety: Uses non-destructive marker values only; never extracts real user data during automated scans.
  • Prerequisite: Target must return query results in the HTTP response body.

Error-Based Detection

Triggers database-specific error messages by injecting malformed SQL syntax. Parses error signatures to identify database engine (MySQL, PostgreSQL, MSSQL, Oracle, SQLite) and confirms injection when stack traces or verbose errors leak to the client.

  • Best for: Rapid identification during development/staging where error suppression is incomplete.
  • Fingerprinting: Error patterns automatically classify the backend RDBMS for targeted payload generation.
  • Note: Low yield in production environments with proper error handling; combine with boolean/time methods.

Safe Testing Configuration

SQL Injection Scanner Pro defaults to non-destructive operation, but misconfiguration can cause unintended side effects. Follow these guidelines for safe testing:

  • Read-only mode: Enabled by default (--safe-mode). Blocks any payload containing INSERT, UPDATE, DELETE, DROP, ALTER, or EXEC. Override explicitly with --allow-write only in isolated test environments.
  • Rate limiting: Default 10 requests/second per target. Adjust with --rps <n> to avoid triggering WAFs or degrading service.
  • Authorization: Always obtain written authorization before scanning third-party systems. The scanner logs all requests with timestamps for audit compliance.
  • Test environment parity: Validate against staging/QA environments first. Production scans should use read-only mode with reduced concurrency.
  • Data sanitization: Reports redact extracted data by default. Use --no-redact only when explicit data exposure evidence is required for remediation tickets.
  • Exclusion lists: Configure --exclude-param <name> to skip sensitive parameters (e.g., payment fields, authentication tokens).

Verify that a specific endpoint uses parameterized queries. Sends benign typed inputs and analyzes query plan leakage or ORM signature patterns.

}

Returns pass/fail per parameter with evidence.

Remediation Guidance

Every finding includes actionable remediation steps tailored to the detected database and framework:

  • Parameterized queries: Replace string concatenation with prepared statements. The scanner provides language-specific examples (Python/psycopg2, Node/pg, Java/JDBC, PHP/PDO, Go/database/sql).
  • ORM usage: Verify ORM query builders are not bypassed with raw SQL. Enable ORM-safe mode validation via --verify-parameterization.
  • Input validation: Apply allowlist validation for numeric IDs and enum parameters. Reject unexpected characters before query construction.
  • Least privilege: Database accounts used by applications should lack DROP, ALTER, and FILE privileges. Scanner flags excessive permissions when error-based detection reveals schema metadata.
  • WAF rules: Deploy SQLi signature rules as defense-in-depth, not primary control. Recommended CRS rule IDs: 942100–942490.
  • Verification: Re-scan after remediation using --baseline <previous-report.json> to confirm fix effectiveness and detect regressions.

Troubleshooting

  • No vulnerabilities detected but manual testing confirms injection: Increase detection sensitivity with --confidence-threshold 0.6 (default 0.8). Check if WAF is blocking scanner payloads; use --stealth mode to rotate User-Agent and add randomized delays.
  • High false positive rate: Enable --strict-validation to require multi-method confirmation. Review findings with confidence <0.8 manually; export low-confidence results separately with --min-confidence 0.8.
  • Scan hangs on time-based detection: Target may have variable latency. Increase baseline samples with --timing-samples 20 or disable time-based method with --methods boolean,union,error.
  • Authentication failures on protected endpoints: Pass session cookies via --cookie "session=abc123" or headers via --header "Authorization: Bearer ...". For OAuth flows, use --auth-flow client_credentials with client ID/secret.
  • License activation fails: Verify system clock is synchronized (NTP). Offline activation available via sqli-scanner-pro auth activate --offline with challenge-response code from dashboard.
  • CI/CD pipeline timeout: Reduce scope with --max-parameters 20 or run async via API mode with webhook callback on completion.
  • Report missing evidence: Ensure --capture-responses is enabled (default off for storage efficiency). Response bodies stored in ~/.sqli-scanner/evidence/; configure retention with --evidence-retention-days 30.
