AI Agents Are Now Hacking at Machine Speed. Your Defenses Aren't Ready.

November 16, 2026 · 10 min read

On November 13, the FBI published a FLASH advisory about ARTEX, an open-source penetration testing framework that uses AI agents to automate intrusions. The bureau says some attacks went from initial scan to privileged access in under three hours. The operator didn't need to be an expert. The agents did the work.

ARTEX was released on GitHub in July by a developer known as Autumn-27, later identified as Chinese security engineer Li Puhua. It was meant for authorized testing. By October, reports of abuse prompted the developer to pull the repository. That didn't stop anything. Community forks, archived copies, localized versions, and a commercial "ARTEX PRO" edition kept it available. As of early November, Censys counted more than 1,600 publicly exposed ARTEX consoles. The real number is certainly higher.

This isn't theoretical. The FBI says ARTEX has been used since at least August against financial services, government agencies, defense contractors, healthcare systems, semiconductor companies, energy providers, and legal firms across multiple countries. South Korean banks lost personal data on roughly 67,000 people. A ConnectWise supply-chain compromise let attackers reach over 2,250 Microsoft 365 tenants. CrowdStrike tracked a Chinese espionage group called Vapor Panda using ARTEX against more than 200 organizations in 14 countries.

What Makes ARTEX Different

Automated attack tools aren't new. Metasploit has existed for two decades. Cobalt Strike has powered red teams and threat actors alike since 2012. What's different about ARTEX is the integration layer between human intent and machine execution.

ARTEX doesn't ship its own AI model. Instead, it connects to external LLMs — Claude, GPT, DeepSeek, GLM, Grok, Kimi — and translates high-level objectives into commands executed by specialized agents. You describe what you want in plain language. The framework figures out how to get there, chains techniques together, adapts when paths fail, and keeps going with minimal human input.

The FBI's advisory notes that Chinese models dominate observed usage because they offer capable inference at low cost with fewer observable guardrails when framed as penetration testing. Amazon's CISO CJ Moses described campaigns where stolen API keys paid for the LLM inference powering further credential theft — a self-sustaining loop where the attack funds itself.

This compresses the timeline defenders have traditionally relied on. Reconnaissance that took days now takes minutes. Credential spraying, privilege escalation, lateral movement, and data staging happen in sequence without waiting for a human operator to review results and decide what to try next. Three hours from first contact to domain admin isn't a worst-case scenario anymore. It's the documented baseline.

Why this matters for small businesses: ARTEX specifically targets overlooked systems — partner portals, employee applications, legacy services, third-party integrations, sales-support tools. These are exactly the systems small businesses tend to secure last (or never). Attackers know this. The framework exploits it systematically.

What Actually Happened in Known Attacks

The ConnectWise incident illustrates the pattern. Attackers compromised application identities used by ConnectWise's cloud backup service (formerly SkyKick). Those identities had permissions previously granted by customers. Using ARTEX, the attackers attempted authentication against more than 2,250 downstream Microsoft 365 tenants. In some environments, they reached privileged access and made changes that Microsoft warns can persist even after credential resets.

Huntress identified at least 162 compromised tenants. Microsoft attributed the campaign to Storm-0940, a China-state-aligned threat actor. ARTEX accelerated reconnaissance, password spraying, and cloud permission abuse across all targets simultaneously. Most attempts failed. Some didn't.

In South Korea, a Chinese-speaking attacker combined ARTEX with Claude Code agents to hit Shinhan Bank, KB Kookmin Bank, and Hana Bank. CrowdStrike found the attacker's exposed infrastructure containing ARTEX configuration files and Claude Code session histories documenting the intrusions. South Korean police arrested seven suspects linked to attacks against more than 90 organizations, with ARTEX reportedly used in most of them. Authorities said the gang stole approximately 8.2 million records.

Vapor Panda used ARTEX against more than 200 organizations across 14 countries. The AI agents performed reconnaissance, exploited vulnerabilities, deployed web shells, stole credentials, and pursued alternative attack paths when initial attempts failed. At least nine organizations were confirmed compromised.

What Defenders Should Do Now

The FBI's advisory includes indicators of compromise — IP addresses, command-and-control infrastructure, suspicious network patterns. But the bureau also warns that IP-based IOCs rot quickly. Static signatures won't save you here.

1. Monitor for Behavioral Bursts, Not Just Signatures

ARTEX generates high-volume automated traffic that triggers alerts. The problem is speed: by the time your SOC triages the alert, the intrusion may already be complete. Tune detection for abnormal authentication rates, unusual cloud privilege escalations, sudden spikes in API calls, unexpected data transfers, and new administrative sessions outside business hours. Behavioral signals catch what static IOCs miss.

2. Secure Internet-Facing Applications Aggressively

ARTEX excels at finding forgotten systems. Audit every internet-facing application your organization operates. Remove unused endpoints. Enforce MFA everywhere. Rate-limit authentication APIs. Restrict cloud administration interfaces to known IP ranges or VPN-only access. If a system doesn't need to be public, make it private.

3. Review Third-Party Application Permissions

The ConnectWise attack succeeded because customers had granted broad permissions to a third-party application identity. Review every OAuth app, SAML provider, and API integration connected to your Microsoft 365 tenant, Google Workspace, or cloud infrastructure. Remove unused grants. Reduce scopes. Monitor for permission changes. Treat application identities like service accounts with privileged access.

4. Assume Compromise and Segment Accordingly

If an attacker reaches privileged access in three hours, your detection window is essentially zero. Design networks assuming breach. Limit lateral movement. Separate critical assets from general user environments. Use jump hosts for administrative access. Log everything to independent storage that survives credential compromise.

5. Deploy Independent Monitoring

If your SIEM, logging, and alerting live in the same environment as the systems being attacked, they fail when those systems fail. Run monitoring on separate infrastructure. The Bigger Picture

ARTEX isn't the only autonomous attack framework, and it won't be the last. The underlying trend is clear: AI-assisted tooling reduces the skill floor for complex intrusions while compressing timelines below human response capability. Smaller threat groups can now run concurrent campaigns at scales previously reserved for well-funded nation-states.

This landed the same week as the Vanderbilt ransomware attack, N-able N-central zero-days, ScreenConnect MSP compromises, Microsoft Patch Tuesday fixing over 1,000 vulnerabilities including an actively exploited Outlook flaw, and Operation Endgame disrupting Gootloader infrastructure. Infrastructure failures and security incidents don't schedule themselves conveniently. They stack.

The businesses that survive aren't the ones with perfect defenses. They're the ones that assumed automation would eventually outrun manual response and built accordingly. Start there.
