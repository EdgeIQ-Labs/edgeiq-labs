Overview

UptimePing monitors your websites, APIs, and services from multiple global locations to detect outages before your users do. It supports HTTP/HTTPS, TCP port, and DNS checks with configurable intervals and multi-channel alerting. Designed for SaaS teams, DevOps engineers, and MSPs who need reliable uptime visibility without infrastructure overhead.

  • Checks from 30+ global PoPs (North America, Europe, Asia-Pacific)
  • HTTP(s), TCP, and DNS check types with custom headers/auth
  • Instant alerts via Email, SMS, Slack, Discord, PagerDuty, or webhook
  • Public status pages with real-time metrics and incident history
  • REST API for programmatic monitor management and data export

Setup

Adding a Monitor

Create a new check via the dashboard or API:

# Add an HTTP check (every 60 seconds from 3 regions)
curl -X POST https://api.edgeiqlabs.com/v1/uptimeping/checks \
  -H "Authorization: Bearer $EDGEIQ_API_KEY" \
  -d '{
    "name": "Production API",
    "type": "http",
    "target": "https://api.example.com/health",
    "interval": 60,
    "regions": ["us-east", "eu-west", "ap-south"],
    "expected_status": 200,
    "timeout": 10
  }'

Intervals & Regions

Choose check frequency from 30s to 1 hour. Select specific regions or use auto for geographic distribution. More frequent checks consume more quota but reduce mean-time-to-detect.

Alert Channels

Configure one or more notification targets per monitor. Alerts fire on state change (UP → DOWN or DOWN → UP) after confirmation from ≥2 regions to prevent false positives.

Status Pages

Create a branded public status page at status.yourdomain.com or edgeiqlabs.status.io/your-page. Includes:

  • Real-time uptime % and response time graphs (24h/7d/30d/90d)
  • Scheduled maintenance windows with auto-start/end
  • Incident timeline with post-mortem support
  • Subscriber notifications via email/RSS/webhook
  • Custom CNAME, logo, colors, and footer links
# Create a status page via API
curl -X POST https://api.edgeiqlabs.com/v1/uptimeping/status-pages \
  -H "Authorization: Bearer $EDGEIQ_API_KEY" \

    "logo_url": "https://acme.com/logo.svg"

Troubleshooting

Common Issues

False positive downtime alerts: Increase confirmation threshold to 3 regions or add a secondary check type (e.g., TCP + HTTP). Transient network blips rarely affect multiple PoPs simultaneously.

Check failing with timeout: Verify target is reachable from public internet. Use timeout: 15 for slow endpoints. Check if WAF/firewall blocks our IP ranges (list available in dashboard).

SMS alerts not arriving: Confirm E.164 format (+country code). Test with /alerts/test. Carrier delays can reach 5 minutes during peak hours.

Status page shows stale data: Browser cache. Hard refresh (Ctrl+Shift+R) or append ?v=timestamp. Data updates every 60s server-side.

API returns 429 Too Many Requests: Rate limit is 100 req/min for Starter, 600 req/min for Pro. Implement exponential backoff. Bulk operations should use batch endpoints where available.
