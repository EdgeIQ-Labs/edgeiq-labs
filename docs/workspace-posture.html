Overview

Workspace Posture Pro continuously monitors your cloud infrastructure across AWS, GCP, and Azure for misconfigurations, exposed secrets, and compliance violations. It automatically checks S3 bucket permissions, IAM policies, security groups, storage ACLs, network configurations, and more. Designed for DevSecOps teams, cloud architects, and compliance officers who need real-time visibility into their cloud security posture without manual auditing.

  • Multi-cloud support: AWS, GCP, and Azure in a single dashboard
  • Continuous monitoring for misconfigurations and exposed secrets
  • Deep inspection of S3 buckets, IAM policies, security groups, and network ACLs
  • Automated compliance mapping against CIS Benchmarks, NIST, and SOC 2
  • Optional auto-remediation for low-risk findings
  • REST API for integration into CI/CD pipelines and SOAR workflows

Setup

Connect your cloud providers using read-only roles. Workspace Posture Pro never modifies your infrastructure during scans unless auto-remediation is explicitly enabled.

AWS Integration

Create a cross-account IAM role with the SecurityAudit managed policy or a custom least-privilege policy. Provide the Role ARN and External ID in the Workspace Posture Pro dashboard.

# Example AWS CLI command to create the audit role
aws iam create-role \
  --role-name EdgeIQPostureAudit \
  --assume-role-policy-document file://trust-policy.json

aws iam attach-role-policy \
  --role-name EdgeIQPostureAudit \
  --policy-arn arn:aws:iam::aws:policy/SecurityAudit

GCP Integration

Create a Service Account with the Viewer and Security Reviewer roles. Download the JSON key file and upload it securely via the Workspace Posture Pro onboarding wizard.

# Example gcloud command
gcloud iam service-accounts create edgeiq-posture \
  --display-name="EdgeIQ Posture Scanner"

gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
  --member="serviceAccount:edgeiq-posture@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/viewer"

Azure Integration

Register an application in Microsoft Entra ID (formerly Azure AD) and create a Service Principal Name (SPN). Assign the built-in Reader and Security Reader roles at the subscription level.

# Example Azure CLI command
az ad sp create-for-rbac \
  --name "EdgeIQPosturePro" \
  --role "Reader" \
  --scopes /subscriptions/YOUR_SUBSCRIPTION_ID
All credentials are encrypted at rest using AES-256. We recommend rotating access keys every 90 days.

Remediation Steps

Every finding includes plain-English remediation steps, exact CLI commands, and Infrastructure-as-Code (Terraform/CloudFormation) snippets to fix the issue. For example:

# Remediation for: Public S3 Bucket (Critical)
# 1. Block public access
aws s3api put-public-access-block \
  --bucket my-sensitive-bucket \
  --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

# 2. Verify configuration
aws s3api get-public-access-block --bucket my-sensitive-bucket

Auto-Remediation

Workspace Posture Pro can optionally apply fixes automatically for low-risk, reversible misconfigurations. Auto-remediation is disabled by default and must be explicitly opted into per rule.

  • Scope: Limited to Low and Medium severity findings (e.g., enabling default encryption, adding missing tags, blocking public ACLs on newly created buckets).
  • Safety: High and Critical findings always require manual approval to prevent unintended service disruption.
  • Audit Trail: Every automated change is logged with a timestamp, the rule that triggered it, and a one-click rollback option.
  • Permissions: Requires elevated write permissions beyond the standard read-only audit role. Configure a separate remediation role scoped only to allowed actions.
# Enable auto-remediation for a specific rule via CLI
workspace-posture rules update s3-block-public-access \
  --auto-remediate true \
  --max-severity medium
Test auto-remediation rules in a staging environment before applying them to production accounts.

Troubleshooting

Common Issues

Permission denied errors during scan: Verify that the IAM role, Service Account, or SPN has the required read-only policies attached. Check for SCPs (Service Control Policies) or Azure Policy restrictions blocking the audit account. Run workspace-posture diagnose auth --provider aws to validate permissions.

Scan timeouts on large environments: Accounts with thousands of resources may exceed default API rate limits. Increase the timeout threshold in your scan configuration or partition scans by organizational unit (OU) or resource group.

# Increase scan timeout to 30 minutes
workspace-posture config set scan_timeout 1800

Missing findings for known misconfigurations: Ensure the specific resource type is included in your Scan Configuration. If using event-driven continuous scanning, verify that CloudTrail or Audit Log integrations are active and forwarding events to Workspace Posture Pro.

False positives: Suppress expected configurations by adding exceptions. Use workspace-posture exceptions add --finding-id XYZ --reason "Approved exception". Exceptions are tracked in the compliance report.

Auto-remediation failed: Check the remediation role's permissions. The remediation role requires explicit write access to the target resource. Review the audit log under /api/workspace-posture/remediation/logs for the exact API error returned by the cloud provider.
