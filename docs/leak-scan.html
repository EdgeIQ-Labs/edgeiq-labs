Overview

Leak Scan continuously monitors public-facing sources for exposed secrets, API keys, database credentials, and sensitive configuration files. It scans GitHub, GitLab, Bitbucket, Pastebin, Ghostbin, S3 buckets, Azure Blobs, and GCP Storage to detect leaks before attackers exploit them.

  • Monitor custom keywords, regex patterns, and entropy-based secret detection
  • Coverage across 6+ source types with unified alerting
  • Severity scoring based on credential type and exposure scope
  • Remediation guidance with rotation checklists per finding type
  • REST API for integration into SIEM, SOAR, and DevSecOps pipelines

Setup

Monitored Keywords

Configure what Leak Scan searches for using exact strings, regex, or built-in detectors:

# Add a keyword monitor
leak-scan keyword add "AKIA[0-9A-Z]{16}" --type regex --label "AWS Access Key"

# Add an exact string (e.g., internal project codename)
leak-scan keyword add "XJ9-INTERNAL-API" --type exact --label "Internal API Token"

# Enable built-in detectors
leak-scan detector enable github-token slack-webhook stripe-key gcp-service-account

# List active monitors
leak-scan keyword list

Exclusion Lists

Reduce false positives by excluding known-safe patterns, test repos, or documented examples:

# Exclude a specific repository
leak-scan exclude add repo:myorg/documentation-examples

# Exclude a file path pattern
leak-scan exclude add path:**/test/fixtures/**

# Exclude a known safe hash/token
leak-scan exclude add token:EXAMPLE_KEY_DO_NOT_USE

# View exclusions
leak-scan exclude list
Exclusions are applied at scan time. Existing findings matching a new exclusion are not auto-closed — review and dismiss them manually.

Finding Details

Each finding includes structured metadata for triage and response:

FieldDescription
finding_idUnique identifier for the leak record
sourcePlatform where the leak was found (github, pastebin, s3, etc.)
urlDirect link to the exposed content
matched_keywordThe keyword or detector that triggered the match
severitycritical / high / medium / low based on credential type
first_seenTimestamp of initial detection
snippetRedacted context around the match (max 500 chars)
authorUploader/commit author when available
repo_or_bucketRepository name or storage bucket identifier
Snippets are redacted by default. Full content is never stored — only the matched portion with surrounding context for verification.

Troubleshooting

Common Issues

No findings despite known leaks: Verify keywords are correctly configured with leak-scan keyword list. Test with a known-public test repo containing a dummy secret.

High false positive rate: Add exclusions for example configs, test fixtures, and documentation repos. Use --type regex instead of exact matches for variable-format secrets.

Source authentication failing: Re-authorize with leak-scan source auth github. Tokens expire after 90 days for some platforms.

Webhook alerts not arriving: Test delivery with leak-scan alert test. Check that your endpoint accepts POST with JSON body and returns 2xx within 5 seconds.

Scan stuck or slow: Check rate limits on source platforms. Pro plans include higher rate limits and parallel scanning across sources.
