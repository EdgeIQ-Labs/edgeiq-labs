API Endpoint Discovery

Overview

EdgeIQ Labs API Endpoint Discovery identifies hidden, undocumented, and deprecated API endpoints across your web applications. Combining passive JavaScript parsing, intelligent active fuzzing, and OpenAPI specification gap analysis, this tool surfaces attack surface areas that traditional crawlers miss.

Designed for security researchers and DevSecOps teams who need comprehensive API visibility without generating excessive noise or triggering WAFs.

Quick Start

# Install via npm
npm install -g @edgeiq/api-discovery

# Run passive discovery on a target
edgeiq-api-discover --target https://app.example.com --mode passive

# Full discovery with spec diffing
edgeiq-api-discover --target https://app.example.com --spec openapi.yaml --output json

Discovery Methods

Passive JS Parsing

Statically analyzes bundled JavaScript files to extract endpoint references without making additional requests. Identifies:

  • Fetch/XHR URL patterns in minified code
  • Route definitions from SPA frameworks (React Router, Vue Router)
  • GraphQL operation names and fragments
  • Environment-specific base URLs and API prefixes

Active Fuzzing

Intelligently probes for endpoints using context-aware wordlists derived from passive analysis. Features rate limiting, response signature clustering, and automatic backoff on 429/5xx responses.

OpenAPI Spec Gap Analysis

Compares discovered endpoints against your existing OpenAPI/Swagger specifications to identify:

  • Undocumented production endpoints
  • Deprecated routes still responding
  • Parameter schema drift between spec and implementation
  • Authentication requirement mismatches

Integration with SurfaceMap

Discovered endpoints automatically enrich your SurfaceMap asset inventory. Enable sync with:

edgeiq-api-discover --target https://app.example.com --surfacemap-sync

Endpoints are tagged with discovery method, confidence score, and last-seen timestamp for prioritization in your attack surface management workflow.

API Reference

POST /v1/discover
Content-Type: application/json
Authorization: Bearer <api_key>

{
  "target": "https://app.example.com",
  "modes": ["passive", "active", "spec-diff"],
  "spec_url": "https://app.example.com/openapi.json",
  "rate_limit": 10,
  "output_format": "json"
}

Response includes endpoints[] array with path, method, source, confidence, and metadata fields.

Safe Testing Rules

⚠️ Important: Always obtain written authorization before running active discovery against any target. Unauthorized scanning may violate computer fraud laws and terms of service.
  • Respect robots.txt and security.txt directives by default
  • Active mode requires explicit --authorized flag confirmation
  • Default rate limit: 5 req/s; configurable via --rate-limit
  • No data exfiltration attempts; only endpoint existence validation
  • Automatic PII redaction in logs and output files

Troubleshooting

IssueSolution
No endpoints found in passive modeVerify JS bundles are accessible; check for CSP blocking inline scripts; try --deep-parse for obfuscated code
Excessive false positivesAdd custom exclude patterns via --exclude-patterns file.txt; increase confidence threshold with --min-confidence 0.7
Rate limited by targetReduce --rate-limit; enable --adaptive-backoff; use proxy rotation with --proxy-pool
Spec diff shows all endpoints as undocumentedVerify spec URL returns valid OpenAPI 3.x; check base path alignment with --spec-base-path /api/v1
