Evidence Collector Documentation

Form-based evidence collection reference for HIPAA, OSHA, and SOC2 compliance audits.

Overview

Evidence Collector is a streamlined compliance evidence management tool designed for organizations undergoing HIPAA, OSHA, or SOC2 audits. Employees upload screenshots, policy acknowledgments, sign-off documents, and other artifacts through a simple form interface. Each submission is automatically tagged to the relevant control framework identifier, organized by auditor-ready categories, and exportable as a structured ZIP bundle.

  • Price: $99/month per organization (flat rate, unlimited users and evidence items).
  • Billing: Monthly via Stripe; cancel anytime with no lock-in.
  • Storage: Cloudflare KV with base64 encoding; 25MB max per file, 1-year retention default.
  • Auth: JWT-based manager tokens issued at subscription activation.
  • Export format: ZIP archive with cover sheet and per-control folder structure.

Setup

  1. Subscribe: Complete checkout at /evidence-collector/ using Stripe price ID price_1UdBJxRC1NZ20yDT0LKs4D30.
  2. Receive token: After successful payment, your organization’s JWT manager token is emailed to the billing contact. This token includes your org_id claim and manager role.
  3. Distribute upload access: Share the upload form URL with employees who need to submit evidence. They do not need individual accounts — only managers require API tokens.
  4. Map controls: Prepare a list of control identifiers (e.g., HIPAA_164.308(a)(1), SOC2_CC6.1, OSHA_1910.134) that correspond to your audit scope. Submitters select from this list when uploading.
  5. Test submission: Use the curl example below to verify your token works and files are stored correctly before rolling out to staff.

API Reference

All endpoints require the X-Evidence-Token header containing a valid JWT with role: manager and your organization’s org claim.

Submit Evidence

POST /api/evidence-collector/submit

Upload a single evidence file tagged to a specific control.

  • Content-Type: multipart/form-data
  • Fields:
    • file (required): Screenshot, PDF, image, or document. Max 25MB.
    • control_id (required): Framework control identifier (e.g., HIPAA_164.312(a)(1)).
    • description (optional): Free-text explanation of what this evidence demonstrates.
  • Returns: 201 Created with evidence_id, filename, size_bytes, and submitted_at.
curl -X POST https://edgeiqlabs.com/api/evidence-collector/submit \
  -H "X-Evidence-Token: YOUR_JWT_TOKEN" \
  -F "file=@screenshots/access-review-q3.png" \
  -F "control_id=HIPAA_164.308(a)(4)" \
  -F "description=Quarterly access review sign-off from IT director"

List Evidence

GET /api/evidence-collector/list

Retrieve all evidence records for your organization, optionally filtered by control.

  • Query params:
    • org (optional): Override org_id (defaults to token’s org claim).
    • control (optional): Filter to a single control identifier.
  • Returns: Summary stats (total_evidence, controls_covered, pending_review, approved) plus array of evidence metadata sorted newest-first.
curl -G https://edgeiqlabs.com/api/evidence-collector/list \
  -H "X-Evidence-Token: YOUR_JWT_TOKEN" \
  --data-urlencode "control=SOC2_CC7.2"

Export Audit Bundle

POST /api/evidence-collector/export

Generate a ZIP archive containing all evidence organized by control folder, plus a cover sheet with audit metadata.

  • Body: JSON with optional controls array to filter exports.
    • org_id (optional): Defaults to token’s org.
    • controls (optional): Array of control IDs. Omit to export everything.
  • Returns: application/zip stream with filename compliance-evidence-{org_id}-{date}.zip.
curl -X POST https://edgeiqlabs.com/api/evidence-collector/export \
  -H "X-Evidence-Token: YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"controls": ["HIPAA_164.308", "HIPAA_164.310"]}' \
  -o audit-bundle.zip

Authentication

Tokens are HMAC-signed JWTs with two base64-encoded parts separated by a dot. The payload must include:

  • org: Your organization identifier (assigned at checkout).
  • role: Must be manager for all write operations.
  • exp (optional): Unix timestamp expiration. Expired tokens are rejected.

Tokens are signed server-side using your organization’s secret derived from EVIDENCE_JWT_SECRET. Never share or embed tokens in client-side code. Rotate tokens annually or immediately if compromised.

Storage & Limits

  • File size: Maximum 25MB per upload. Files are base64-encoded for KV storage, so effective binary limit is ~18MB after encoding overhead.
  • Retention: Evidence records expire after 365 days by default. Contact support@edgeiqlabs.com to extend retention for regulatory requirements (HIPAA mandates 6 years minimum).
  • Supported formats: PNG, JPG, PDF, DOCX, XLSX, TXT, CSV. Executable files (.exe, .sh, .bat) are rejected.
  • Index consistency: The org index (evidence:index:{org_id}) updates synchronously on submit. List queries read from this index; allow 1-2 seconds propagation delay after uploads.

Troubleshooting

  • 401 Unauthorized: Verify your JWT token has not expired and contains both org and role: manager claims. Regenerate via your subscription dashboard if needed.
  • 413 File Too Large: Reduce file size below 25MB. Compress images or split large PDFs into multiple submissions.
  • Missing evidence in list: Wait 2 seconds after upload before querying. If still missing, check that the control_id spelling matches exactly (case-sensitive).
  • Export returns empty ZIP: Confirm at least one evidence record exists for the requested controls. Run GET /list first to verify coverage.
  • CORS errors in browser: All endpoints return Access-Control-Allow-Origin: *. If blocked, check that your request includes the X-Evidence-Token header (preflight may fail without it).
  • Token rotation: Old tokens remain valid until expiration. To force-revoke, contact support with your org_id to invalidate the signing secret.
