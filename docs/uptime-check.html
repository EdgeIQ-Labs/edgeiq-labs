Overview

Uptime Check monitors your websites and APIs from multiple global locations, detecting downtime before your users do. Configure check intervals, select monitoring regions, receive instant alerts via your preferred channels, and share real-time status with customers through hosted status pages.

  • HTTP/HTTPS, TCP, DNS, and ICMP monitoring protocols
  • Check intervals from 30 seconds to 24 hours
  • Multi-region verification to eliminate false positives
  • Alerts via email, SMS, Slack, Discord, PagerDuty, and webhooks
  • Public and private status pages with custom branding
  • REST API for programmatic monitor management

Setup

Adding URLs

Add monitors via the dashboard or API. Each monitor requires a target URL or host and a check interval.

# Add an HTTPS monitor (check every 60 seconds)
curl -X POST https://api.edgeiqlabs.com/v1/monitors \
  -H "Authorization: Bearer $EDGEIQ_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Production Website",
    "type": "https",
    "target": "https://example.com",
    "interval": 60,
    "locations": ["us-east", "eu-west", "ap-southeast"]
  }'

Location Selection

Monitors run from geographically distributed points of presence. Selecting multiple locations reduces false positives caused by regional outages or network issues.

When multiple locations are configured, a site is marked DOWN only when a majority of locations fail consecutive checks. Single-location failures trigger a warning but not an alert.

Status Pages

Publish real-time uptime data to a branded status page. Status pages can be public or password-protected.

  • Custom subdomain (status.yourcompany.com) or EdgeIQ-hosted URL
  • Per-monitor uptime percentages and response time graphs
  • Incident history with post-mortem fields
  • Subscriber notifications for status changes
  • Embeddable widget for your own website
# Create a public status page
curl -X POST https://api.edgeiqlabs.com/v1/status-pages \
  -H "Authorization: Bearer $EDGEIQ_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Acme Corp Status",
    "slug": "acme-corp",
    "public": true,
    "monitors": ["mon_abc123", "mon_def456"]
  }'

Troubleshooting

Common Issues

False positive downtime alerts: Add additional monitoring locations. Single-location checks are susceptible to regional network issues. Use at least 3 locations for production services.

Checks failing with timeout: Increase the timeout value (default 10s). Some CDNs and WAFs throttle automated requests. Add User-Agent: EdgeIQ-UptimeCheck/1.0 to allowlist headers if needed.

SSL certificate errors: Ensure intermediate certificates are served correctly. Test with openssl s_client -connect example.com:443. Enable ignore_ssl_errors: true only for self-signed internal services.

Alerts not arriving: Verify channel configuration with the test endpoint: POST /v1/alert-channels/{id}/test. Check spam folders for email. Review rate limits for webhook-based channels.

Status page not updating: Confirm monitors are assigned to the status page. Cached responses may take up to 60 seconds to refresh. Purge CDN cache if using a custom domain.
