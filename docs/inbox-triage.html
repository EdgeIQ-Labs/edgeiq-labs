Overview

Inbox Triage uses AI to automatically classify incoming emails by priority, draft contextual replies, and route messages to the right team members or folders. It integrates directly with your existing Gmail or Outlook inbox — no new interface to learn.

  • Automatic priority classification (Urgent, Normal, FYI, Spam)
  • Context-aware reply drafting with tone adjustment
  • Smart routing rules based on sender, content, and labels
  • Digest mode: batch low-priority emails into daily summaries
  • Team collaboration: shared triage rules and handoff workflows
  • REST API for custom integrations and automation

Setup

Connecting Your Inbox

Connect your email provider to enable AI processing:

# Connect Gmail account
inbox-triage connect gmail --account user@example.com

# Connect Outlook/Microsoft 365
inbox-triage connect outlook --tenant-id xxxxx --client-id yyyyy

# Verify connection status
inbox-triage connections list
Email access uses OAuth 2.0 with read/write scopes limited to message metadata and drafts. Full mailbox access is never stored on our servers.

Configuring Triage Rules

Define how emails should be classified and routed:

# Set priority keywords
inbox-triage rules add priority urgent --keywords "outage,down,asap,emergency"

# Create routing rule
inbox-triage rules add route support --from "*@customer.com" --folder "Support Queue"

# Enable auto-draft for specific senders
inbox-triage config set auto_draft_enabled true
inbox-triage config set auto_draft_senders "boss@company.com,ceo@company.com"

# View active rules
inbox-triage rules list

Auto-Draft Replies

Inbox Triage generates draft replies based on email context, your writing style, and conversation history. Drafts are saved to your Drafts folder for review before sending.

# Generate draft for latest email
inbox-triage draft generate --thread-id abc123

# Adjust tone (professional, casual, brief)
inbox-triage draft generate --thread-id abc123 --tone brief

# Regenerate with different approach
inbox-triage draft regenerate --draft-id xyz789 --strategy apologetic
Auto-drafts are never sent automatically. You always review and approve before sending.

Digest Mode

Batch low-priority emails into a single daily digest instead of constant notifications:

# Enable digest for FYI category
inbox-triage digest enable --category fyi --time 08:00

# Customize digest format
inbox-triage config set digest_format "bullet_summary"

# Pause digest temporarily
inbox-triage digest pause --until "2026-11-25"

API Reference

All CLI functionality is available via REST API when running inbox-triage serve --port 8402.

Endpoints

MethodPathDescription
GET/api/triage/statusGet current triage stats and queue depth
POST/api/triage/classifyClassify a single email by ID
POST/api/triage/draftGenerate draft reply for a thread
GET/api/triage/rulesList active triage and routing rules
PUT/api/triage/rules/{id}Update an existing rule
GET/api/triage/historyRetrieve classification and action history

Example: Classify Email via API

curl -X POST http://localhost:8402/api/triage/classify \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ***" \
  -d '{
    "message_id": "abc123",
    "include_reasoning": true
  }'

Troubleshooting

Common Issues

OAuth connection fails: Verify your Google/Microsoft app credentials are correct and redirect URI matches. Re-authenticate with inbox-triage connect gmail --force.

Emails not being classified: Check that triage is enabled for the connected account. Run inbox-triage status to verify processing is active.

Drafts not appearing: Confirm write permissions were granted during OAuth setup. Check Drafts folder (not Sent). Use inbox-triage draft test to verify access.

Rules not triggering: Rule syntax may be invalid. Validate with inbox-triage rules validate --rule-id abc. Check logs with inbox-triage logs --tail 50.

API returns 401 Unauthorized: Verify API key is valid. Regenerate with inbox-triage api-key rotate.

High latency on classification: Large attachments slow processing. Set inbox-triage config set max_attachment_size 5MB to skip oversized files.
