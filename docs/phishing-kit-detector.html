Overview

EdgeIQ Labs Phishing Kit Detector identifies and tracks phishing infrastructure by analyzing server fingerprints, hosting provider patterns, and behavioral signals. Unlike traditional URL blocklists, this tool focuses on the underlying kit architecture to detect new campaigns before they are widely reported.

Key capabilities include:

  • Infrastructure Fingerprinting: Identify specific phishing kit versions and configurations.
  • Hosting Pattern Analysis: Detect bulletproof hosting providers and ASN clusters commonly used by threat actors.
  • Takedown Workflow: Streamlined reporting and evidence packaging for registrars and hosting providers.
  • Real-time Alerts: Configurable notifications via webhook, email, or SIEM integration.

Setup

Installation

pip install edgeiq-phishing-detector
export EDGEIQ_API_KEY="your_api_key_here"

Configuration

Create a config.yaml in your project root:

detection:
  fingerprint_db: /var/lib/edgeiq/fingerprints.db
  scan_interval: 300
  max_concurrent: 10

alerting:
  webhook_url: https://hooks.slack.com/services/...
  severity_threshold: medium

takedown:
  auto_package: true
  evidence_dir: ./evidence

Detection Methods

Infrastructure Fingerprinting

The detector analyzes HTTP headers, TLS certificates, JavaScript bundles, and directory structures to identify known phishing kits. Fingerprints are updated weekly from our global honeypot network.

  • Header Analysis: Unique server signatures and custom X- headers.
  • Asset Hashing: SHA-256 hashes of login forms, CSS, and JS payloads.
  • Certificate Transparency: Monitoring CT logs for suspicious domain issuance patterns.

Hosting Pattern Analysis

Identifies infrastructure based on hosting provider reputation, ASN history, and IP neighborhood analysis.

SignalDescriptionWeight
ASN ReputationHistorical abuse score of the autonomous systemHigh
IP VelocityRate of new domain resolutions to the IPMedium
Provider TypeBulletproof vs. legitimate hosting classificationHigh

Behavioral Analysis

Monitors runtime behavior including redirect chains, credential harvesting form submissions, and C2 callback patterns to distinguish active kits from parked or defunct pages.

Takedown Workflow Integration

Automate the evidence collection and reporting process:

  1. Detection: Kit identified with confidence score > 0.85.
  2. Evidence Packaging: Screenshots, source code, WHOIS data, and headers archived.
  3. Report Generation: Standardized abuse report formatted for major registrars.
  4. Submission: Optional API-based submission to participating hosting providers.
Note: Takedown requests are rate-limited to prevent abuse. Premium plans include priority queue access.

Alert Configuration

Configure alerts in config.yaml under the alerting section:

alerting:
  channels:
    - type: webhook
      url: https://api.example.com/alerts
      events: [detection, takedown_complete]
    - type: email
      recipients: [soc@example.com]
      severity: high
  filters:
    exclude_asns: [AS12345]
    min_confidence: 0.7

Troubleshooting

Common Issues

  • False Positives: Adjust min_confidence threshold or add ASN exclusions.
  • Timeout Errors: Increase scan_timeout in config; some kits use delayed redirects.
  • Missing Fingerprints: Run edgeiq-update-db to fetch latest signatures.
