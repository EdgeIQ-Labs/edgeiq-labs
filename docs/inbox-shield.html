Overview

Inbox Shield is an AI-powered email triage and phishing detection tool that connects directly to your Gmail or Outlook inbox via OAuth. It analyzes incoming emails in real time for phishing attempts, suspicious attachments, and social engineering tactics, then auto-categorizes every message into Safe, Suspicious, or Dangerous tiers. Designed for individuals, teams, and enterprises who need proactive email defense without manual filtering rules.

  • Real-time AI analysis of inbound email headers, body, and links
  • Three-tier auto-categorization: Safe, Suspicious, Dangerous
  • Social engineering and impersonation detection
  • Sandboxed attachment scanning with malware detonation
  • Automated triage actions: archive, flag, quarantine, forward
  • REST API for SIEM/SOAR integration

Setup

OAuth Connection

Inbox Shield uses OAuth 2.0 to connect to your mailbox. No passwords are stored or transmitted. The connection flow takes under 60 seconds:

# 1. Navigate to the Inbox Shield dashboard
# https://edgeiqlabs.com/inbox-shield/

# 3. Authenticate through your provider's native OAuth consent screen

# 4. Grant the requested permission scopes

# 5. Inbox Shield begins monitoring new inbound emails immediately

Permission Scopes

Inbox Shield requests only the minimum scopes required for email analysis and triage. No send permissions are ever requested.

False Positive Handling

No detection system is perfect. Inbox Shield provides multiple mechanisms to reduce and correct false positives:

  • User feedback loop: Mark any email as "Not Phishing" to retrain the model for your specific inbox patterns.
  • Allowlists: Add trusted senders, domains, or IP ranges to bypass analysis entirely.
  • Sensitivity slider: Adjust the threshold between tiers. Lower sensitivity reduces false positives at the cost of potentially missing novel attacks.
  • Weekly digest: Review all flagged emails in a summary report to catch misclassifications early.

Attachment Scanning

Email attachments are one of the most common malware delivery vectors. Inbox Shield intercepts and scans attachments before they reach your device.

Scanning Pipeline

  • Static analysis: File type validation (detects extension spoofing), hash lookup against known malware databases, YARA rule matching
  • Sandbox detonation: Suspicious files are opened in an isolated cloud sandbox to observe runtime behavior — registry changes, network callbacks, file drops
  • Macro inspection: Office documents (.docx, .xlsx, .pptm) are scanned for embedded VBA macros, obfuscated scripts, and DDEAUTO payloads
  • Archive unpacking: Nested archives (.zip inside .rar inside .7z) are recursively extracted up to 5 levels deep

Supported File Types

CategoryExtensions
Documents.pdf, .doc, .docx, .xls, .xlsx, .ppt, .pptx, .rtf, .odt
Archives.zip, .rar, .7z, .tar, .gz, .iso
Executables.exe, .msi, .bat, .cmd, .ps1, .scr, .com
Scripts.js, .vbs, .wsf, .py, .sh
Images.jpg, .png, .gif, .svg (scanned for steganography/polyglot payloads)
Attachments exceeding 25 MB are hashed and checked against threat intel feeds but are not detonated in the sandbox due to resource constraints. Enterprise plans support up to 100 MB sandbox analysis.

Compliance

GDPR Data Handling

Inbox Shield processes personal data (email content) under strict GDPR compliance:

  • Lawful basis: Processing is performed under Legitimate Interest (security protection) and explicit user consent via OAuth grant.
  • Data minimization: Only email fields necessary for threat analysis are processed. Marketing emails are classified by header/metadata alone when possible.
  • Encryption: All email data is encrypted in transit (TLS 1.3) and at rest (AES-256).
  • Processing location: EU customers' data is processed exclusively in EU-based data centers (Frankfurt, Amsterdam). US customers use US-East infrastructure.
  • Right to erasure: Disconnecting your OAuth token triggers automatic deletion of all cached email data within 24 hours.
  • DPA available: Data Processing Agreements are provided for Team and Enterprise plans upon request.

Troubleshooting

Common Issues

OAuth connection fails or shows "Access Denied": Ensure your organization's admin hasn't blocked third-party app access. For Google Workspace, an admin must allowlist Inbox Shield's OAuth client ID in Admin Console → Security → API Controls. For Microsoft 365, check Azure AD Conditional Access policies that may block consent flows.

OAuth token expired / stopped scanning: Tokens can expire if unused for 6 months or if you changed your password. Reconnect from the Inbox Shield dashboard — click "Reconnect" next to your mailbox. No historical data is lost.

Legitimate emails marked as Dangerous: This usually happens with internal tools that send automated emails with link-heavy content. Add the sending address or domain to your Allowlist under Settings → Trusted Senders. You can also lower the sensitivity slider by one notch.

Phishing emails reaching inbox unflagged: Novel zero-day phishing campaigns may briefly evade detection. Use the "Report Miss" button on any undetected email — this immediately feeds the sample back into our ML pipeline. Enterprise customers can enable Enhanced Mode for deeper NLP analysis (adds ~200ms latency per email).

Attachments not scanning: Verify the file size is under the plan limit (25 MB Individual/Team, 100 MB Enterprise). Password-protected archives cannot be scanned — these are automatically classified as Suspicious with a note recommending manual review.

API returns 401 Unauthorized: Confirm your API key is active and hasn't been rotated. Keys expire after 1 year by default. Generate a new key from Dashboard → Settings → API Keys.
