Get Started

Overview

Relay provides secure, instant tunnels from your local machine to the public internet. Designed for developers who need to share work-in-progress, test webhooks, or demo applications without deploying to a staging server. Includes custom subdomains, automatic HTTPS termination, and detailed request logging out of the box.

  • Expose any local TCP port to the internet in seconds
  • Custom subdomains on edgeiqlabs.dev or your own domain
  • Automatic HTTPS/TLS termination with valid certificates
  • Real-time request and response logging with replay
  • REST API for programmatic tunnel management

Setup

CLI Installation

# Install via npm
npm install -g @edgeiq/relay

# Or via pip
pip install edgeiq-relay

# Verify installation
relay --version

Authentication

Authenticate once to link your CLI to your EdgeIQ Labs account. Tokens are stored locally at ~/.edgeiq/relay.toml.

# Interactive browser login
relay auth login

# Or use an API token directly
relay auth login --token ei_live_abc123def456

# Verify auth status
relay auth status

# Revoke current session
relay auth logout
API tokens can be generated from the dashboard at edgeiqlabs.com/dashboard/tokens. Use ei_test_ prefixed tokens for non-production work.

Tunnel Creation

Create a tunnel by pointing Relay at a local port. The CLI provisions a public URL instantly.

# Expose local port 3000
relay forward 3000

# Output:
# Tunnel active: https://random-slug.edgeiqlabs.dev → localhost:3000
# Press Ctrl+C to stop.

# Specify protocol (HTTP is default)
relay forward 8080 --proto tcp

# Run in background (daemonized)
relay forward 3000 --daemon

# List active tunnels
relay list

# Stop a specific tunnel
relay stop <tunnel-id>
FlagDescription
--protoProtocol: http (default), https, tcp
--daemonRun tunnel in background
--regionEdge region: us, eu, ap (default: closest)
--inspectEnable local inspection UI on port 4040

Custom Subdomains

Replace random slugs with predictable, branded URLs. Available on all paid plans.

# Use a custom subdomain
relay forward 3000 --subdomain my-app
# → https://my-app.edgeiqlabs.dev

# Use a fully custom domain (requires DNS CNAME setup)
relay forward 3000 --domain dev.mycompany.com

To use a custom domain, add a CNAME record pointing dev.mycompany.com to relay.edgeiqlabs.dev, then verify ownership in the dashboard under Domains.

Subdomain names must be 3–63 characters, alphanumeric plus hyphens. Reserved words and premium short names require the Pro plan.

HTTPS Termination

Relay handles TLS at the edge. Traffic between the client and Relay's edge nodes is encrypted with automatically provisioned certificates. The connection from the edge to your local machine uses a persistent, authenticated WebSocket tunnel.

  • Auto-provisioned Let's Encrypt certificates for *.edgeiqlabs.dev
  • Custom domain certificates issued within 60 seconds of DNS verification
  • TLS 1.2+ enforced; legacy ciphers disabled
  • Optional mTLS for Pro plan users requiring mutual authentication
# Force HTTPS redirect (HTTP requests get 301'd)
relay forward 3000 --https-only

# Enable mTLS with a client CA bundle (Pro only)
relay forward 3000 --mtls-ca ./client-ca.pem

Request Logging

All traffic through your tunnel is logged and inspectable. Use the CLI or the web dashboard to view, filter, and replay requests.

# Stream logs in real time
relay logs <tunnel-id>

# Filter by status code
relay logs <tunnel-id> --status 5xx

# Filter by method
relay logs <tunnel-id> --method POST

# Export logs to JSON
relay logs <tunnel-id> --export logs.json --last 24h

All tunnel operations are available via REST API. Base URL: https://api.edgeiqlabs.com/v1. Authenticate with Bearer token.

  -H "Content-Type: application/json" \
  -d '{

    "https_only": true,
    "region": "us"
  }'

Troubleshooting

Common Issues

Tunnel connects but returns 502 Bad Gateway: Your local server isn't responding on the specified port. Verify the app is running and bound to 127.0.0.1 or 0.0.0.0, not a Docker network alias.

Custom subdomain returns 404: The subdomain may already be claimed by another user. Try a different name or check relay list to confirm your tunnel is active.

Custom domain not resolving: Ensure the CNAME record points exactly to relay.edgeiqlabs.dev (no trailing path). DNS propagation can take up to 5 minutes after verification.

WebSocket connections dropping: Relay supports WebSockets natively, but idle connections timeout after 60s on Starter. Pro plan extends this to 10 minutes. Send ping frames to keep connections alive.

Auth errors (401) on API calls: Confirm your token hasn't expired. Regenerate via relay auth login or the dashboard. Ensure you're using ei_live_ tokens for production API calls.

High latency: Use --region to select an edge node closer to your target audience. Check relay status for current routing path.
