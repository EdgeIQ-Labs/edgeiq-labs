Overview

Sub Alerts monitors specific subdomains for DNS changes, new deployments, certificate rotations, and potential security exposures. Designed for security teams, DevOps engineers, and asset managers who need real-time visibility into their attack surface without manual enumeration.

  • Track unlimited subdomains across multiple root domains
  • Detect DNS record changes (A, AAAA, CNAME, MX, TXT)
  • Identify new subdomains via passive and active discovery
  • Monitor SSL/TLS certificate changes and expiration
  • Instant alerts via email, webhook, Slack, or Discord
  • REST API for integration into SOAR and asset management workflows

Setup

Adding Subdomains

# Add a single subdomain to monitor
sub-alerts add api.example.com

# Add multiple subdomains from a file
sub-alerts add --file subdomains.txt

# Auto-discover and add all known subdomains
sub-alerts discover example.com --add-all

# List monitored subdomains
sub-alerts list

Configuring Alert Channels

# Email alerts
sub-alerts config --alert-email security@example.com

# Webhook (generic)
sub-alerts config --alert-webhook https://hooks.example.com/sub-alerts

# Slack integration
sub-alerts config --slack-webhook https://hooks.slack.com/services/xxx

# Discord integration
sub-alerts config --discord-webhook https://discord.com/api/webhooks/xxx

# Test alert delivery
sub-alerts test-alert
Multiple alert channels can be configured simultaneously. All channels receive identical payloads for redundancy.

  --interval 1800 \

sub-alerts config --global --interval 900 --cert-check

API Reference

All CLI functionality is available via REST API when running sub-alerts serve --port 8401.

Endpoints

GET/api/v1/alertsRetrieve alert history (paginated)

Example: Add Subdomain via API

curl -X POST http://localhost:8401/api/v1/subdomains \
  -H "Content-Type: application/json" \
  -d '{
    "subdomain": "staging.example.com",
    "records": ["A", "AAAA", "CNAME"],
    "cert_check": true,
    "interval": 1800
  }'

Troubleshooting

Common Issues

Subdomain not resolving: Verify the subdomain exists in DNS. Use sub-alerts check staging.example.com to run a one-off diagnostic including DNS lookup, certificate validation, and HTTP probe.

Alerts not delivering: Test with sub-alerts test-alert. Check ~/.edgeiq/logs/sub-alerts.log for SMTP errors, webhook HTTP status codes, or rate-limit responses.

Too many false positives: Narrow monitored record types with --records A,CNAME. Enable --quiet-hours to suppress non-critical alerts during maintenance windows.

Discovery missing subdomains: Increase --discovery-depth or supplement with external wordlists via --wordlist custom.txt. Passive sources may lag behind active infrastructure changes.

Rate limited by DNS provider: Reduce check frequency with --interval 7200 or configure a local DNS cache to reduce upstream queries.
