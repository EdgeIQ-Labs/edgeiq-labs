BrandGuard Documentation

Domain impersonation detection, typosquatting monitoring, and lookalike domain alerts.

Overview

BrandGuard is a continuous brand protection service that monitors the open web for domain impersonation, typosquatting, and lookalike domains targeting your organization. It detects malicious registrations before they reach customers, employees, or partners, reducing phishing risk and brand dilution.

  • Price: $14/month per monitored root domain (flat rate).
  • Billing: Monthly; cancel anytime with no long-term commitment.
  • Coverage: Monitors new gTLDs, ccTLDs, and legacy TLDs across 1,500+ extensions.
  • Detection latency: Newly registered domains are evaluated within 15 minutes of WHOIS propagation.

Core capabilities include:

  • Typosquatting Detection: Identifies homoglyphs, character swaps, missing hyphens, plural/singular variants, and common misspellings of your brand.
  • Lookalike Domain Alerts: Flags domains using visual similarity, keyword stuffing, or subdomain abuse to mimic your brand.
  • Impersonation Scoring: Each candidate receives a threat score (0–100) based on lexical distance, DNS configuration, hosting infrastructure, and historical abuse patterns.
  • Automated Takedown Workflow: One-click takedown requests to registrars and hosting providers with pre-filled abuse reports.
  • API Access: RESTful API for integrating detections into SIEM, SOAR, or internal security dashboards.

Setup

  1. Create account: Sign up at app.edgeiqlabs.com and verify your email address.
  2. Add protected domains: Navigate to Settings → Protected Domains and enter each root domain you want to monitor (e.g., example.com). Wildcards are not supported; add each variant explicitly.
  3. Configure detection sensitivity: Adjust the threat score threshold (default: 60) under Settings → Detection Rules. Lower thresholds increase coverage but may generate more false positives.
  4. Set alert channels: Configure email, Slack, webhook, or PagerDuty notifications under Settings → Alert Channels.
  5. Verify ownership (optional): Add a TXT record to your DNS to unlock automated takedown authority for your domains. Without verification, takedowns require manual confirmation.

Monitoring begins immediately after adding a domain. Initial baseline scan completes within 1 hour; ongoing scans run continuously.

Monitored Domains Configuration

Manage your protected domains via Settings → Protected Domains or the API (POST /v1/domains).

  • Root domains only: Enter example.com, not www.example.com or *.example.com. Subdomains are automatically included in monitoring scope.
  • Multiple domains: Each root domain counts as one billable unit. Adding example.com and example.net incurs two $14/mo charges.
  • Removal: Deleting a domain stops monitoring immediately and prorates the current billing cycle.
  • Historical data: Detections for removed domains are retained for 90 days for audit purposes, then permanently deleted.
  • Bulk import: Upload a CSV file with one domain per line via Settings → Bulk Import. Maximum 100 domains per upload.

Detection Rules

BrandGuard applies multiple detection strategies to identify malicious domains:

  • Levenshtein Distance: Flags domains within edit distance ≤2 of your protected domain (configurable). Catches character swaps, insertions, and deletions.
  • Homoglyph Matching: Detects visually similar characters across Unicode scripts (e.g., Cyrillic а vs. Latin a, zero-width spaces).
  • Keyword Combination: Identifies domains combining your brand name with high-risk terms like login, secure, verify, account, support, or update.
  • Subdomain Abuse: Monitors for your brand appearing in subdomains of unrelated domains (e.g., example.phishing-site.com).
  • TLD Risk Weighting: Applies higher threat scores to domains registered in TLDs with historically high abuse rates (e.g., .xyz, .top, .work).
  • DNS & Hosting Signals: Evaluates MX records, SPF/DKIM configuration, hosting provider reputation, and SSL certificate issuance patterns.

Custom rules can be added via Settings → Custom Rules using regex patterns against newly registered domain names. Custom rules trigger alerts independently of the threat score threshold.

Alert Channels

Configure notification delivery under Settings → Alert Channels:

  • Email: Default channel. Sends digest summaries every 6 hours or instant alerts for Critical threats (score ≥90). Supports multiple recipients and distribution lists.
  • Slack: Post alerts to a specific channel via incoming webhook. Includes threat score, domain link, and one-click takedown button.
  • Webhook: POST JSON payload to any HTTPS endpoint. Payload includes domain, threat score, detection method, timestamp, and WHOIS metadata. Retries failed deliveries up to 3 times with exponential backoff.
  • PagerDuty: Trigger incidents for Critical threats only. Maps threat score to PagerDuty severity.
  • SMS: Opt-in for Critical alerts only. Requires phone number verification. Limited to 10 messages/day to prevent abuse.

All channels support suppression windows to pause notifications during planned maintenance or known false-positive periods.

Takedown Workflow

When a malicious domain is confirmed, initiate takedown directly from the dashboard or API:

  1. Review detection: Examine the domain’s threat score, registration details, DNS records, and screenshot preview (if available).
  2. Classify verdict: Mark as Malicious, Suspicious, Benign, or False Positive. Verdicts train future detection models.
  3. Generate abuse report: Click Takedown → Generate Report to create a pre-formatted complaint with evidence attachments (WHOIS record, DNS snapshot, phishing page screenshot).
  4. Submit to registrar/host: For verified domains, click Submit Takedown to send the report directly to the registrar’s abuse contact. Unverified domains display the abuse email address for manual submission.
  5. Track status: Monitor takedown progress in Takedowns → Active Cases. Status updates (Acknowledged, In Progress, Resolved, Rejected) are pulled automatically via registrar APIs where supported.

Average takedown time is 48–72 hours for cooperative registrars. BrandGuard escalates unresponsive cases after 5 business days and provides legal template letters for non-compliant providers.

API Reference

Base URL: https://api.edgeiqlabs.com/v1

Authentication: Bearer token obtained from Settings → API Keys.

Endpoints

  • GET /domains — List all protected domains and their monitoring status.
  • POST /domains — Add a new protected domain. Body: {"domain": "example.com"}.
  • DELETE /domains/{domain} — Remove a protected domain.
  • GET /detections — Retrieve detections filtered by domain, date range, threat score, or verdict. Supports pagination (?page=1&per_page=50).
  • GET /detections/{id} — Get full detection detail including WHOIS, DNS, and screenshot URLs.
  • POST /detections/{id}/verdict — Update detection verdict. Body: {"verdict": "malicious", "notes": "Confirmed phishing kit"}.
  • POST /takedowns — Initiate takedown for a detection. Body: {"detection_id": "det_abc123"}.
  • GET /takedowns/{id} — Check takedown case status and history.

Rate Limits

  • 100 requests/minute per API key.
  • Exceeding limits returns HTTP 429 with Retry-After header.

Troubleshooting

  • No detections appearing: Verify the protected domain is spelled correctly and active. New domains take up to 1 hour to appear in results. Check Settings → Detection Rules threshold; raise it temporarily to test sensitivity.
  • Excessive false positives: Increase the threat score threshold or add benign domains to the allowlist under Settings → Allowlist. Mark individual detections as False Positive to improve model accuracy.
  • Missed typosquat: Ensure the variant falls within configured Levenshtein distance. Add custom regex rules for brand-specific misspellings not caught by default algorithms.
  • Takedown rejected: Review registrar’s rejection reason in Takedowns → Case Details. Some registrars require additional evidence (e.g., trademark certificate, court order). Use Generate Legal Letter for escalated cases.
  • Webhook not receiving events: Verify endpoint returns HTTP 2xx within 10 seconds. Check Settings → Alert Channels → Webhook Logs for delivery failures and response bodies. Whitelist egress IPs listed in Settings → Network.
  • API authentication errors: Regenerate API key if compromised. Ensure token is passed in Authorization: Bearer <token> header. Keys expire after 1 year; rotate proactively.
  • Billing discrepancy: Invoice reflects active domain count at billing cycle start. Mid-cycle additions prorate automatically. Contact billing@edgeiqlabs.com with invoice ID for adjustments.
