Overview

Mailflare is a self-hosted email platform designed for developers who need full control over their email infrastructure. It provides production-ready SMTP/IMAP services, programmable webhook integrations, and native MCP (Model Context Protocol) access for AI agent workflows. Deploy on your own domain with Docker-based setup and manage everything via REST API or CLI.

  • Full SMTP/IMAP server with TLS and authentication
  • Custom domain support with automated DNS validation
  • Webhook integrations for inbound/outbound email events
  • MCP server for AI agent email access and automation
  • REST API for programmatic email management
  • Docker Compose deployment with one-command setup

Setup

DNS Configuration

Before deploying Mailflare, configure the following DNS records for your domain:

TypeNameValuePurpose
Amail<your-server-ip>Mail server hostname
MX@mail.yourdomain.comInbound mail routing
TXT@v=spf1 mx a:mail.yourdomain.com ~allSPF sender policy
TXT_dmarcv=DMARC1; p=quarantine; rua=mailto:dmarc@yourdomain.comDMARC policy
TXTmail._domainkeyv=DKIM1; k=rsa; p=<public-key>DKIM signing key
Use mailflare dns check yourdomain.com to validate all required records before deployment. Missing or misconfigured records will cause delivery failures.

Docker Deployment

# Clone the Mailflare repository
git clone https://github.com/edgeiq-labs/mailflare.git
cd mailflare

# Configure environment
cp .env.example .env
nano .env  # Set DOMAIN, ADMIN_EMAIL, DKIM keys

# Start services
docker compose up -d

# Verify status
docker compose ps
mailflare health

Mailflare runs three containers: smtp (port 25/587), imap (port 993), and api (port 8400). All data persists in named Docker volumes.

Creating Mailboxes

# Create a new mailbox via CLI
mailflare mailbox create user@yourdomain.com --password 'securepass'

# Or via API
curl -X POST http://localhost:8400/api/v1/mailboxes \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"address": "user@yourdomain.com", "password": "securepass"}'

Webhook Integrations

Mailflare sends HTTP POST requests to configured endpoints when email events occur. Use webhooks to trigger workflows, update databases, or notify external systems.

Supported Events

EventTriggerPayload Fields
email.receivedInbound message acceptedfrom, to, subject, message_id
email.sentOutbound message deliveredto, message_id, status
email.bouncedDelivery failureto, message_id, bounce_reason
mailbox.createdNew mailbox provisionedaddress, created_at

Configuring Webhooks

# Add a webhook endpoint
mailflare webhook add https://hooks.example.com/mailflare \
  --events email.received,email.bounced \
  --secret whsec_your_signing_secret

# Test delivery
mailflare webhook test https://hooks.example.com/mailflare

# List active webhooks
mailflare webhook list
All webhook payloads include an X-Mailflare-Signature header. Verify signatures using HMAC-SHA256 with your configured secret to prevent spoofing.

MCP Access

Mailflare includes a native MCP (Model Context Protocol) server that allows AI agents to read, send, and manage email without custom API integration code.

Available Tools

ToolDescription
list_emailsList messages in a mailbox with pagination and filters

send_emailSend an outbound message from a managed mailbox
search_emailsFull-text search across subject, body, and headers

MCP Server Configuration

{
  "mcpServers": {
    "mailflare": {
      "command": "docker",
      "args": ["exec", "-i", "mailflare-api", "mailflare", "mcp", "serve"],
      "env": {
        "MAILFLARE_API_KEY": "your_api_key_here"
      }
    }
  }
}

Add this configuration to your Claude Desktop, Cursor, or other MCP-compatible client. The server exposes read/write tools scoped to the authenticated API key.

API Reference

All functionality is available via REST API at http://localhost:8400 (or your configured host). Authenticate with Authorization: Bearer <API_KEY>.

  }'

Troubleshooting

Common Issues

Emails not being received: Run mailflare dns check yourdomain.com to verify MX, SPF, and DKIM records. Check docker compose logs smtp for rejection reasons.

SMTP authentication fails: Ensure the mailbox exists (mailflare mailbox list) and the password was set correctly. Reset with mailflare mailbox reset-password user@yourdomain.com.

Webhooks not firing: Test with mailflare webhook test <url>. Verify the endpoint returns HTTP 2xx within 10 seconds. Check docker compose logs api for delivery errors.

MCP tools unavailable: Confirm the MAILFLARE_API_KEY environment variable is set and valid. Regenerate with mailflare api-key regenerate.

Docker containers failing to start: Check port conflicts on 25, 587, 993, and 8400. Ensure no other MTA (Postfix, Exim) is bound to these ports. Run docker compose logs for specific errors.

DKIM signing not working: Verify the DKIM public key in DNS matches the private key in .env. Regenerate keys with mailflare dkim generate and update your TXT record.
