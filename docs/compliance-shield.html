Compliance Shield Documentation

HIPAA compliance monitoring reference for small healthcare organizations.

Overview

Compliance Shield is a continuous HIPAA compliance monitoring service designed for small healthcare practices, clinics, and health-tech startups. It automates evidence collection, control verification, and audit-ready reporting across administrative, physical, and technical safeguards defined in 45 CFR Parts 160 and 164.

  • Price: $299/month per organization (flat rate, up to 50 covered entities).
  • Billing: Monthly or annual; annual prepay applies a 10% discount.
  • Data residency: All monitoring data stored in US-East (AWS us-east-1); no cross-border transfer.
  • Retention: Evidence artifacts retained 7 years by default; configurable per retention policy.

Setup

  1. Organization onboarding: Complete the intake form with NPI, TIN, business associate agreements (BAAs), and system inventory.
  2. Integration provisioning: Connect EHR/EMR API keys, cloud infrastructure accounts (AWS/GCP/Azure), identity provider (Okta/Azure AD), and endpoint management (Jamf/Intune).
  3. Baseline scan: Initial full-scope assessment runs within 24 hours of integration completion; results populate the dashboard gap analysis.
  4. Policy import: Upload existing HIPAA policies or use built-in templates; map each policy to applicable controls.
  5. Verification schedule: Set automated check cadence (daily, weekly, or monthly) per control category.

Monitored Controls

Compliance Shield monitors 87 discrete controls mapped to HIPAA Security Rule standards:

  • Access Controls (§164.312(a)(1)): Unique user IDs, MFA enforcement, role-based access reviews, session timeout configuration, emergency access procedures.
  • Audit Controls (§164.312(b)): Log completeness across EHR, cloud, and identity systems; log retention verification; tamper-evidence checks.
  • Integrity Controls (§164.312(c)(1)): Encryption at rest/transit verification, checksum validation on ePHI exports, database integrity constraints.
  • Authentication (§164.312(d)): Password policy compliance, certificate rotation, SSO configuration drift detection.
  • Transmission Security (§164.312(e)(1)): TLS version enforcement, cipher suite validation, API endpoint encryption status.
  • Physical Safeguards (§164.310): Facility access logs, workstation positioning audits, device disposal chain-of-custody records.
  • Administrative Safeguards (§164.308): Risk assessment currency, workforce training completion rates, contingency plan test results, vendor BAA expiration tracking.

Alerts

Alerts trigger when a monitored control deviates from its expected state or when evidence collection fails.

  • Severity levels: Critical (immediate breach risk), High (control failure requiring action within 24h), Medium (drift requiring remediation within 7 days), Low (informational or upcoming deadline).
  • Delivery channels: Email (default), Slack webhook, PagerDuty (Critical only), SMS (opt-in for Critical/High).
  • Suppression rules: Configure maintenance windows, acknowledged exceptions, or duplicate alert deduplication windows per control.
  • Escalation: Unacknowledged Critical alerts escalate to secondary contacts after 4 hours; High alerts escalate after 24 hours.
  • Audit trail: Every alert includes timestamped evidence snapshot, affected asset identifier, and linked regulatory citation.

Reports

Generate reports from the Dashboard → Reports tab or via API (GET /v1/reports).

  • Risk Assessment Report: Current risk posture, identified gaps, remediation priority matrix, trend over prior 12 months.
  • Audit Readiness Report: Evidence inventory mapped to each HIPAA standard, missing evidence flags, attestation sign-off status.
  • Vendor Risk Summary: BAA status, third-party security questionnaire responses, last audit date, open findings.
  • Training Completion Report: Workforce module completion rates, overdue assignments, quiz score distributions.
  • Custom Reports: Select controls, date range, and format (PDF, CSV, JSON); schedule recurring generation and delivery.

All reports include cryptographic hash for tamper verification and are signed with your organization’s compliance key.

Team Management

Navigate to Settings → Team to manage users and roles.

  • Roles:
    • Admin: Full access including billing, integrations, and policy editing.
    • Compliance Officer: View all controls, generate reports, acknowledge alerts, edit policies.
    • Auditor: Read-only access to evidence and reports; no configuration changes.
    • IT Staff: View technical controls, receive assigned remediation tasks, upload evidence.
  • Inviting members: Enter email address, assign role, and send invitation; invitees must verify email and complete MFA enrollment before access is granted.
  • SSO enforcement: Enable SAML/OIDC requirement to block password-only logins for your domain.
  • Audit log: All team actions (invites, role changes, removals) logged with actor, timestamp, and IP.

Troubleshooting

  • Integration sync failures: Verify API credentials have not expired; check IP allowlist includes Compliance Shield egress ranges (documented in Integrations → Network). Re-authenticate via Settings → Integrations → Refresh Token.
  • Missing evidence artifacts: Confirm source system logging is enabled and retention meets minimum requirements; run Diagnostics → Evidence Collector Test to validate connectivity.
  • False positive alerts: Use Alert → Suppress → Add Exception with justification; exceptions require Compliance Officer approval and expire after 90 days unless renewed.
  • Report generation timeout: Large date ranges or custom reports spanning >1 year may exceed 60-second limit; narrow scope or schedule as async job via API.
  • SSO login loop: Clear browser cookies for *.edgeiqlabs.com; verify IdP assertion consumer service URL matches value in Settings → SSO → Metadata.
  • Billing discrepancies: Invoice line items reflect active entity count at billing cycle start; mid-cycle additions prorate automatically. Contact billing@edgeiqlabs.com with invoice ID for adjustments.
