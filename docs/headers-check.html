Overview

Headers Check analyzes HTTP response headers for security best practices, misconfigurations, and missing protections. It inspects every header your server sends, compares it against current OWASP and Mozilla guidelines, and produces a letter grade reflecting your overall security posture. Designed for developers, security teams, and site owners who need continuous assurance that their HTTP headers haven't drifted or regressed.

  • Scan any public URL for HTTP security headers in seconds
  • Detailed per-header analysis with pass/fail/warning status
  • Letter-grade scoring (A+ through F) based on weighted header checks
  • Scheduled recurring scans with change detection and alerts
  • REST API for integration into CI/CD pipelines and dashboards

Setup

Adding Domains

Add domains through the dashboard or CLI. Each domain is scanned at its root path by default; you can specify additional paths per domain.

# Add a single domain via CLI
headers-check add example.com

# Add multiple domains from a file
headers-check add --file domains.txt

# Add a domain with specific paths to check
headers-check add example.com --paths /,/login,/api/v1

Header Checks

Headers Check evaluates the following HTTP security headers. Each header is checked for presence, correct syntax, and secure configuration values.

HSTS (Strict-Transport-Security)

Enforces HTTPS connections and prevents protocol downgrade attacks. Headers Check validates max-age (minimum recommended: 31536000), presence of includeSubDomains, and optional preload directive.

# Passing example
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload

# Failing: max-age too short, no subdomain coverage
Strict-Transport-Security: max-age=3600

CSP (Content-Security-Policy)

Controls which resources the browser is allowed to load. Headers Check flags unsafe directives like unsafe-inline, unsafe-eval, wildcard sources (*), and missing default-src. Report-only mode (Content-Security-Policy-Report-Only) is detected and scored lower than enforced policies.

X-Frame-Options

Prevents clickjacking by controlling whether the page can be embedded in frames. Valid values: DENY or SAMEORIGIN. Deprecated in favor of CSP frame-ancestors, but still checked for backward compatibility.

CORS (Access-Control-Allow-Origin)

Evaluates Cross-Origin Resource Sharing configuration. Wildcard origins (*) on authenticated endpoints are flagged as critical. Missing Access-Control-Allow-Credentials handling and overly permissive Allow-Methods generate warnings.

X-Content-Type-Options

Must be set to nosniff to prevent MIME-type sniffing. Any other value or absence is a failure.

Referrer-Policy

Controls how much referrer information is sent with requests. Recommended values: strict-origin-when-cross-origin, no-referrer, or same-origin. The legacy unsafe-url value is flagged.

Permissions-Policy

Replaces the deprecated Feature-Policy header. Controls access to browser features (camera, microphone, geolocation). Headers Check verifies the header is present and not set to allow-all (*).

Grading System

Each scan produces a letter grade from A+ to F based on a weighted scoring model. Critical headers (HSTS, CSP, X-Content-Type-Options) carry more weight than informational ones (Server disclosure, X-XSS-Protection).

GradeScore RangeDescription
A+95–100All critical headers present with optimal configuration
A85–94All critical headers present, minor improvements possible
B70–84Most headers configured, one or two non-critical gaps
C55–69Missing important headers or weak configurations
D40–54Multiple critical headers missing or misconfigured
F0–39Severe security gaps; immediate remediation required
Grades are recalculated whenever scan results change. Grade history is plotted on the dashboard so you can track improvement over time.

Troubleshooting

Common Issues

Grade dropped unexpectedly: Check if a recent deployment changed server configuration, CDN settings, or reverse proxy rules. Use headers-check diff example.com --last 2 to compare the two most recent scans side by side.

Headers present in browser but not in scan results: Some CDNs or WAFs inject headers only for browser user-agents. Headers Check uses a standard HTTP client; configure --user-agent to match if needed, or verify headers are applied at the origin level.

CSP warnings despite working application: Headers Check flags unsafe-inline and unsafe-eval because they weaken XSS protection. If your framework requires them, consider migrating to nonce-based or hash-based CSP directives. The warning won't prevent a passing grade if all other headers are strong, but it caps your score below A+.

Scan timeout or connection refused: Ensure the target URL is publicly accessible. Firewalls blocking non-browser requests will cause failures. Use --timeout 30 to increase the wait time for slow servers.

Redirect chains losing headers: By default, Headers Check follows redirects and reports headers from the final destination. Use --no-follow to inspect intermediate redirect responses if headers are stripped during the chain.

API rate limit exceeded: Starter plans allow 100 API calls/hour; Pro allows 1000. Space out batch requests or upgrade your plan. Rate limit headers (X-RateLimit-Remaining) are included in every API response.
