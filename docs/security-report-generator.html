Security Report Generator Documentation

Automated pentest report generation, risk scoring frameworks, and remediation prioritization.

Overview

Security Report Generator automates the creation of professional penetration testing reports from raw scan data, manual findings, and vulnerability assessments. It ingests results from popular scanners (Nmap, Burp Suite, Nessus, OpenVAS), enriches them with risk scores, and produces polished deliverables tailored to different audiences—executives, technical teams, or external clients.

  • Price: $9/month per user.
  • Billing: Monthly subscription; cancel anytime.
  • Data handling: All processing occurs in-memory or within your configured workspace. No raw scan data is retained on EdgeIQ servers beyond the active session unless you enable cloud sync.
  • Supported inputs: Nmap XML, Burp Suite XML/JSON, Nessus CSV/XML, OpenVAS XML, custom JSON schema, manual Markdown entries.

Quick Start

  1. Install the CLI: 
    pip install edgeiq-security-report
  2. Initialize a project: 
    sec-report init my-pentest --template executive
  3. Import scan data: 
    sec-report import nmap-scan.xml --format nmap
sec-report import burp-findings.json --format burp
  4. Add manual findings (optional): 
    sec-report add-finding --title "Broken Authentication" --severity high --cvss 8.1 --description "Session tokens are not invalidated after logout."
  5. Generate the report: 
    sec-report generate --output report.pdf --format pdf

The generated file report.pdf will appear in your current working directory with all imported and manual findings scored, prioritized, and formatted according to the selected template.

Report Templates

Templates control structure, tone, and depth. Select one during init or switch at generation time with --template.

Executive Template

Designed for C-suite and board-level audiences. Focuses on business impact, overall risk posture, and strategic recommendations. Technical details are collapsed into appendices. Includes an executive summary paragraph auto-generated from finding severity distribution, a risk trend chart if historical data is provided, and a top-5 remediation priority list mapped to business objectives.

Technical Template

Intended for engineering, DevOps, and security teams. Every finding includes full reproduction steps, affected endpoints, CVSS vector breakdown, evidence screenshots (if attached), and specific remediation commands or code patches. Findings are grouped by attack surface (network, web application, infrastructure) rather than severity alone.

Client-Facing Template

For consultancies delivering reports to external customers. Combines an accessible executive summary with a detailed technical body. Supports white-label branding (see Branding Customization). Includes a scope-of-work section, methodology description, limitations/caveats page, and a formal sign-off block. Sensitive internal tooling references are automatically sanitized.

Risk Scoring

Each finding is scored using one or more frameworks. The generator normalizes disparate scanner outputs into a unified risk model.

CVSS v3.1 / v4.0

Common Vulnerability Scoring System vectors are parsed directly from scanner output or manually specified. Base, Temporal, and Environmental metrics are supported. When only a base score exists, the system can compute environmental adjustments based on asset criticality tags you assign during import.

FAIR (Factor Analysis of Information Risk)

For organizations using quantitative risk analysis, the FAIR module accepts loss event frequency and probable loss magnitude inputs. These can be entered manually per-finding or derived from historical incident data via sec-report import-fair-data incidents.csv. Output is expressed as annualized loss expectancy (ALE) ranges.

EPSS (Exploit Prediction Scoring System)

CVEs identified in findings are automatically cross-referenced against the latest EPSS dataset to retrieve exploit probability scores. This enriches prioritization: a CVSS 7.5 vulnerability with an EPSS of 0.92 ranks higher than a CVSS 9.0 with an EPSS of 0.01. EPSS data refreshes on each generation run or can be pinned to a specific date for audit consistency.

Remediation Priority Matrix

The generator produces a Remediation Priority Matrix that maps every finding across two axes: exploitability (derived from EPSS, CVSS Attack Vector/Complexity, and known public exploits) and business impact (derived from CVSS Impact metrics, FAIR ALE, or manual asset-criticality tags).

QuadrantCriteriaAction
Critical / ImmediateHigh exploitability + High impactRemediate within 24–72 hours. Assign dedicated resources.
High / Short-termHigh exploitability + Medium impact, or Low exploitability + High impactRemediate within 1–2 sprint cycles.
Medium / PlannedMedium exploitability + Medium impactSchedule into backlog; apply compensating controls.
Low / AcceptLow exploitability + Low impactDocument acceptance rationale; revisit quarterly.

The matrix is rendered as a visual scatter plot in PDF/HTML exports and as a sortable table in DOCX. You can override quadrant placement for any finding using sec-report set-priority <finding-id> --quadrant critical.

Branding Customization

White-label reports to match your organization or consultancy brand. Create a brand.yaml file in your project root:

company_name: "Acme Security Consulting"
logo_path: "./assets/logo.png"
primary_color: "#1a73e8"
secondary_color: "#34a853"
font_family: "Inter, sans-serif"
header_text: "Confidential — Prepared for {client_name}"
footer_text: "© 2026 Acme Security Consulting. All rights reserved."
cover_page: true
toc_depth: 3

Apply it at generation time:

sec-report generate --output report.pdf --format pdf --brand brand.yaml

The logo is embedded at 300 DPI for print-quality PDF output. Colors propagate to charts, headings, table borders, and the cover page accent bar. Variables like {client_name}, {engagement_date}, and {report_id} are resolved from project metadata set during init.

Export Formats

PDF

Print-ready output via WeasyPrint. Supports embedded fonts, vector charts, page numbers, headers/footers, and PDF/A-2b compliance for long-term archival. Password protection available via --pdf-password.

DOCX

Microsoft Word format generated through python-docx. Preserves heading hierarchy, tables, images, and styles so clients can edit or append content. Table of contents is inserted as a Word-native TOC field that updates on open.

HTML

Self-contained single-file HTML with inline CSS and base64-encoded images. No external dependencies required to view. Includes a collapsible sidebar navigation for large reports. Suitable for hosting on internal wikis or sharing via secure link.

API Reference

The Security Report Generator exposes a REST API for CI/CD integration and programmatic report generation. Base URL: https://api.edgeiqlabs.com/v1/reports. Authenticate via Bearer token obtained from your dashboard.

Create a Report Job

POST /v1/reports/jobs
Content-Type: application/json
Authorization: Bearer <token>

{
  "project": "my-pentest",
  "template": "technical",
  "format": "pdf",
  "brand": "default",
  "findings_url": "https://storage.example.com/findings.json"
}

Returns {"job_id": "rpt_abc123", "status": "queued"}.

Check Job Status

GET /v1/reports/jobs/{job_id}
Authorization: Bearer <token>

Returns {"status": "completed", "download_url": "...", "expires_at": "2026-11-13T10:00:00Z"}. Download URLs expire after 7 days.

List Findings

GET /v1/reports/projects/{project}/findings?severity=high&page=1&per_page=50
Authorization: Bearer <token>

Upload Scan Data

POST /v1/reports/projects/{project}/import
Content-Type: multipart/form-data
Authorization: Bearer <token>

file=@scan-results.xml
format=nmap

Troubleshooting

  • Import parsing errors: Verify the scanner output format matches the --format flag. Nmap XML must be generated with -oX; Burp exports should use the native XML or JSON format, not HTML. Run sec-report validate input.xml to check schema conformance before importing.
  • PDF generation fails on Linux: Ensure WeasyPrint system dependencies are installed (libpango-1.0-0, libharfbuzz0b, libffi-dev). On minimal containers, install the weasyprint-system-deps metapackage or use the Docker image edgeiq/sec-report:latest.
  • Missing EPSS scores: EPSS lookups require CVE identifiers. If your scanner reports vendor-specific IDs without CVE mapping, EPSS enrichment is skipped for those findings. Manually attach CVEs via sec-report edit-finding <id> --cve CVE-2026-XXXX.
  • Brand logo not rendering: Logo path in brand.yaml must be relative to the project root or an absolute path. PNG and SVG are supported; JPEG may lose transparency on cover pages. Maximum recommended dimensions: 800×200px.
  • DOCX table overflow: Findings with extremely long descriptions or wide CVSS vector strings may exceed page margins. Use --truncate-descriptions 500 to cap length, or switch to landscape orientation with --orientation landscape.
  • API rate limits: The API enforces 60 requests per minute per token. For bulk imports, use the multipart upload endpoint which accepts up to 50MB per request rather than submitting individual findings.
  • FAIR calculations showing zero ALE: Ensure both loss event frequency and loss magnitude fields are populated. Missing values default to zero rather than being estimated. Check sec-report fair-summary to identify incomplete entries.
