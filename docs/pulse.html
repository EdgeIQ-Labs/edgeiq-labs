Overview

EdgeIQ Pulse is a continuous security monitoring platform designed for DevOps teams, security engineers, and IT administrators who need centralized visibility across their entire infrastructure. Pulse aggregates findings from all EdgeIQ scanners—including Repo Scanner, Port Scanner, XSS Scanner, CertWatch Pro, and more—into a unified dashboard with trend analysis, real-time alerting, and automated compliance reporting.

  • Multi-project support with role-based access control
  • Real-time alerting via email, webhook, Slack, and PagerDuty
  • Trend analysis with historical finding comparison
  • Automated HIPAA, SOC 2, and PCI DSS compliance reports
  • REST API for CI/CD integration and custom workflows

Setup

Prerequisites

  • Active EdgeIQ Labs account with at least one scanner license
  • API key generated from Account Settings → API Keys
  • At least one project created in the Pulse dashboard

Connecting Scanners

# Link Port Scanner to Pulse
pulse connect --scanner port-scanner --api-key YOUR_API_KEY

# Link Repo Scanner
pulse connect --scanner repo-scanner --api-key YOUR_API_KEY

# Link CertWatch Pro
pulse connect --scanner certwatch-pro --api-key YOUR_API_KEY

# Verify connected scanners
pulse status

API Key Configuration

All Pulse API requests require authentication via Bearer token. Store your API key securely and never commit it to version control.

# Set API key as environment variable
export EDGEIQ_API_KEY="ei_live_xxxxxxxxxxxxxxxxxxxx"

# Or configure in ~/.edgeiq/config.yaml
pulse config set api_key ei_live_xxxxxxxxxxxxxxxxxxxx
API keys are scoped per project. Use separate keys for staging and production environments to maintain isolation.

Interpreting Metrics

The Finding Summary widget uses color coding: red for Critical, orange for High, yellow for Medium, blue for Low. A rising trend line indicates new exposures or regressions; a declining line shows successful remediation. The Compliance Score is calculated as (passing controls / total applicable controls) × 100.

Filtering Findings

# Filter by severity
pulse findings list --severity critical

# Filter by scanner
pulse findings list --scanner port-scanner

# Filter by date range
pulse findings list --since 2026-10-01 --until 2026-11-01

# Combine filters
pulse findings list --severity high --scanner xss-scanner --status open

Severity Thresholds

Configure minimum severity levels per channel to reduce alert fatigue:

# Email gets everything
pulse alert config --channel email --min-severity low

# Slack gets Medium and above
pulse alert config --channel slack --min-severity medium

# PagerDuty gets Critical only
pulse alert config --channel pagerduty --min-severity critical

# Webhook with custom payload template
pulse alert config --channel webhook --template /etc/pulse/webhook-payload.json
Test alerts before going live: pulse alert test --channel slack. Check delivery logs with pulse alert logs --last 24h.

Generating Reports

# Generate HIPAA compliance report
pulse compliance generate --framework hipaa --format pdf --output hipaa-report.pdf

# Generate SOC 2 report for specific date range
pulse compliance generate --framework soc2 --since 2026-08-01 --until 2026-11-01 --format json

# Schedule weekly PCI report
pulse compliance schedule --framework pci --frequency weekly --day monday --email compliance@example.com

# List available frameworks
pulse compliance list-frameworks
Compliance reports include evidence artifacts (scan timestamps, finding IDs, remediation proof). Retain exports for auditor review. Reports are regenerated on-demand; scheduled reports auto-deliver to configured email.

API Reference

All Pulse functionality is available via REST API. Base URL: https://api.edgeiqlabs.com/v1/pulse

Endpoints

MethodPathDescription
GET/projectsList all projects accessible to the authenticated user
POST/projectsCreate a new project
GET/projects/{id}/findingsList findings with filtering and pagination
GET/projects/{id}/trendsRetrieve trend data for dashboard graphs
POST/alertsCreate a new alert rule
GET/alertsList configured alert rules
DELETE/alerts/{id}Delete an alert rule
POST/compliance/generateGenerate a compliance report
GET/compliance/reports/{id}Download a generated report

Example: List Project Findings

curl -H "Authorization: Bearer $EDGEIQ_API_KEY" \
  "https://api.edgeiqlabs.com/v1/pulse/projects/proj_abc123/findings?severity=critical&status=open&limit=50"

Example: Create Alert Rule

curl -X POST https://api.edgeiqlabs.com/v1/pulse/alerts \
  -H "Authorization: Bearer $EDGEIQ_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "proj_abc123",
    "channel": "slack",
    "min_severity": "high",
    "target": "#security-alerts"
  }'

Troubleshooting

Common Issues

No data showing in dashboard: Verify scanners are connected with pulse status. Ensure API key has read permissions for the target project. Check scanner schedules—data appears after the first completed scan cycle.

Alerts not firing: Confirm alert rule severity threshold isn't higher than current findings. Test delivery with pulse alert test --channel <name>. Review pulse alert logs for HTTP errors or rate limits. For Slack, verify bot is invited to the target channel.

Compliance report missing controls: Some frameworks require specific scanners. HIPAA needs Port Scanner + Header Inspector; PCI requires XSS Scanner + CertWatch. Run pulse compliance gaps --framework hipaa to see missing data sources.

API returns 401 Unauthorized: Regenerate API key if expired. Ensure key scope includes the target project ID. Keys prefixed ei_test_ only work against sandbox endpoints.

Trend graph shows flatline: Trends require ≥7 days of historical data. New projects show empty trends until sufficient scans accumulate. Force a backfill with pulse trends backfill --days 30 (Pro/Enterprise only).
