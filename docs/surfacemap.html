Overview

SurfaceMap provides comprehensive visibility into your API attack surface. It automatically discovers endpoints across passive traffic analysis, active scanning, and log ingestion to identify shadow APIs, deprecated versions, and unauthenticated surfaces. Continuous monitoring ensures new exposures are detected and alerted in real-time.

Setup

Prerequisites

  • EdgeIQ Labs account with active SurfaceMap subscription
  • API key generated from the Dashboard → Settings → API Keys
  • Network access to target infrastructure (for active discovery)

Installation

npm install @edgeiq/surfacemap-cli
# or
docker pull edgeiqlabs/surfacemap:latest

Authentication

export SURFACEMAP_API_KEY="sk_live_xxxxxxxxxxxxxxxxxxxx"
surfacemap auth verify

Configuration

Create a surfacemap.config.yaml in your project root:

project: "my-api-platform"
targets:
  - domain: "api.example.com"
    methods: [passive, active]
  - cidr: "10.0.0.0/24"
    methods: [active]

discovery:
  passive:
    sources: [cloudflare, aws-alb, nginx-access]
  active:
    rate_limit: 100req/s
    ports: [80, 443, 8080, 8443]
  traffic:
    integrations: [datadog, splunk]

monitoring:
  interval: "1h"
  alerts:
    channels: [slack, email]
    severity_threshold: "medium"

Discovery Methods

Method Description Best For
Passive Analyzes existing logs, DNS records, certificate transparency, and CDN configs without sending packets. Shadow API detection, historical endpoint recovery
Active Performs intelligent HTTP probing, port scanning, and fuzzing against defined targets. Verifying live endpoints, finding hidden admin panels
Traffic Ingests real-time telemetry from SIEM, observability platforms, and proxy logs. Runtime validation, catching ephemeral endpoints

Continuous Monitoring

SurfaceMap runs scheduled discovery cycles based on your configured monitoring.interval. Each cycle compares results against the previous baseline to detect:

  • New endpoints appearing in production
  • Removed or deprecated routes still responding
  • Changes in authentication requirements
  • Certificate expirations or domain hijacking risks
Note: Monitoring state is persisted server-side. CLI interruptions do not reset baselines.

API Reference

List Discovered Endpoints

GET /v1/projects/{project_id}/endpoints?status=active&limit=100
Authorization: Bearer sk_live_xxx

Trigger On-Demand Scan

POST /v1/projects/{project_id}/scans
Content-Type: application/json

{
  "target": "api.example.com",
  "methods": ["active", "passive"],
  "config_override": { "rate_limit": "50req/s" }
}

Retrieve Scan Results

GET /v1/scans/{scan_id}/results
# Returns JSON with endpoints, metadata, and risk scores

Alert Configuration

Configure alerts in surfacemap.config.yaml under monitoring.alerts:

alerts:
  channels:
    - type: slack
      webhook: "https://hooks.slack.com/services/..."
    - type: email
      recipients: ["secops@example.com"]
  rules:
    - event: "new_endpoint_detected"
      severity: "high"
      notify: true
    - event: "auth_removed"
      severity: "critical"
      notify: true

Troubleshooting

Symptom Cause Resolution
401 Unauthorized Invalid or expired API key Regenerate key in Dashboard; verify SURFACEMAP_API_KEY env var
No endpoints discovered Target unreachable or WAF blocking scanner Whitelist SurfaceMap IPs (surfacemap ips list); check firewall rules
High false positives Overly broad CIDR or wildcard domains Narrow target scope; add exclusions in config
Alerts not firing Webhook misconfigured or severity threshold too high Test channel with surfacemap alert test --channel slack
