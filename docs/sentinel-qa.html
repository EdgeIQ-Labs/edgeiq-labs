Overview

Sentinel QA continuously tests web applications for broken links, UI regressions, and functional bugs without manual intervention. Designed for development teams, QA engineers, and product owners who need reliable automated testing without maintaining complex test infrastructure.

  • Autonomous crawling with intelligent path discovery
  • Broken link and 404 detection across entire sites
  • Visual regression testing with pixel-level diffing
  • Functional bug detection via DOM state validation
  • Continuous regression tracking with historical baselines
  • REST API for CI/CD integration and custom workflows

Setup

Application URL Configuration

# Initialize Sentinel QA for your application
sentinel-qa init --url https://app.example.com

# Configure authentication (if required)
sentinel-qa auth set --type bearer --token "$APP_TOKEN"

# Verify connectivity and baseline capture
sentinel-qa verify
Sentinel QA requires read access to your application. For authenticated routes, configure credentials via sentinel-qa auth or environment variables. Never commit tokens to version control.

Test Scenario Definition

Define test scenarios in YAML to guide autonomous crawling:

# .sentinel/scenarios.yaml
scenarios:
  - name: "User Login Flow"
    entry_point: "/login"
    assertions:
      - type: element_visible
        selector: "#dashboard"
        timeout: 5000
      - type: no_console_errors

  - name: "Checkout Process"
    entry_point: "/cart"
    max_depth: 3
    assertions:
      - type: status_code
        expected: 200
      - type: element_text
        selector: ".total-price"
        pattern: "^\\$[0-9]+\\.[0-9]{2}$"

Regression Tracking

Sentinel QA maintains historical baselines to detect regressions over time. Baselines are stored per-branch and automatically updated on successful test runs.

# Capture new baseline
sentinel-qa baseline capture --branch main

# Compare current state against baseline
sentinel-qa compare --baseline main --threshold 5%

# View regression history
sentinel-qa history --last 30d --severity high

# Approve visual changes (update baseline)
sentinel-qa baseline approve --run-id abc123 --reason "Redesigned pricing page"
Baselines are stored in .sentinel/baselines/. Add this directory to .gitignore if using local storage, or configure S3/GCS backend for team sharing via sentinel-qa config storage.

Troubleshooting

Common Issues

Crawl fails immediately: Verify the application URL is reachable from the Sentinel QA host. Check sentinel-qa verify output for DNS or TLS errors. For self-signed certs, use --insecure flag.

False positive visual regressions: Dynamic content (timestamps, ads) causes diffs. Add --ignore-selector ".timestamp, .ad-banner" to exclude volatile regions from comparison.

Authentication not persisting: Ensure auth tokens are set correctly with sentinel-qa auth list. For OAuth flows, use --auth-type cookie and provide session cookies directly.

Tests timing out on SPA routes: Increase timeout with --timeout 60 or add explicit wait assertions in scenarios. Sentinel QA waits for network idle by default; override with --wait-until domcontentloaded for faster but less reliable checks.

Baseline storage errors: Verify write permissions on .sentinel/baselines/. For cloud backends, check credentials with sentinel-qa config test-storage.
