Overview

Secrets Scan continuously monitors your Git repositories for accidentally committed API keys, passwords, tokens, and other sensitive credentials. It integrates natively with GitHub, GitLab, and Bitbucket to provide real-time protection against secret leakage in both historical commits and new pushes.

  • Supports GitHub, GitLab, and Bitbucket cloud/self-hosted
  • Detects 200+ secret patterns including AWS, GCP, Azure, Stripe, Slack, and generic tokens
  • Scans full Git history plus incremental checks on every push
  • Auto-revocation hooks for supported providers (GitHub Token, AWS IAM)
  • REST API and webhook integrations for CI/CD and SOAR pipelines

Setup

Repository Connection

Connect your Git provider via OAuth or personal access token. Secrets Scan requires read-only repository access; write permissions are only needed if auto-revocation is enabled.

# Connect a GitHub organization
secrets-scan connect github --org my-org --token ghp_xxxxxxxxxxxx

# Connect a GitLab project
secrets-scan connect gitlab --project-group my-group --token glpat-xxxxxxxxxxxx

# Connect Bitbucket workspace
secrets-scan connect bitbucket --workspace my-workspace --app-password xxxxxxxxxxxx

# List connected repositories
secrets-scan repos list

Secret Patterns

Secrets Scan ships with 200+ built-in regex patterns. You can add custom patterns for internal token formats or domain-specific credentials.

# Add a custom pattern
secrets-scan pattern add "INTERNAL_API_KEY" "(?i)internal[_-]?api[_-]?key[\\s]*=[\\s]*['\"]?[A-Za-z0-9]{32}"

# Test pattern against sample text
secrets-scan pattern test INTERNAL_API_KEY "internal_api_key = abcdef1234567890abcdef1234567890"

# Export all active patterns as JSON
secrets-scan patterns export > custom-patterns.json

Scan Frequency

Configure how often Secrets Scan inspects each repository. Incremental scans run automatically on every push; scheduled deep scans re-inspect full history at your chosen interval.

ModeDefaultDescription
IncrementalOn pushScans only new commits within seconds of push event
Daily Deep02:00 UTCFull-history rescan once per day
Weekly DeepSun 03:00 UTCFull-history rescan once per week
Custom CronUser-definedAny valid cron expression for deep scans
# Set daily deep scan at 04:00 UTC
secrets-scan schedule set my-org/backend-api --deep-cron "0 4 * * *"

# Disable deep scans (incremental only)
secrets-scan schedule set my-org/backend-api --no-deep

# Trigger an immediate full rescan
secrets-scan scan now my-org/backend-api --full-history
Deep scans on repositories with >10k commits may take 5-15 minutes. Schedule during off-peak hours to avoid rate-limit impacts.

Auto-Revocation

For supported providers, Secrets Scan can automatically revoke or rotate compromised credentials upon detection, reducing mean-time-to-remediation from hours to seconds.

ProviderActionRequirements
GitHub Personal Access TokenRevoke token via GitHub APIAdmin org token with admin:org scope
AWS IAM Access KeyDeactivate key + create rotation ticketIAM User with iam:UpdateAccessKey
Slack Bot TokenReinstall app to rotate tokenSlack Admin OAuth with admin.apps:write
Stripe Secret KeyRoll key via Stripe Dashboard APIStripe Restricted Key with api_keys.write
# Enable auto-revocation for a repo
secrets-scan revocation enable my-org/backend-api --providers github,aws

# Dry-run to preview actions without executing
secrets-scan revocation dry-run my-org/backend-api

# View revocation audit log
secrets-scan revocation history my-org/backend-api --last 30d
Auto-revocation is opt-in per repository and requires explicit write-scope credentials. All revocation actions are logged immutably for compliance audits.

Troubleshooting

Common Issues

Repository connection fails: Verify your token has at least read-only repository scope. For GitHub orgs, ensure the OAuth app is approved by org admins. Check secrets-scan connect test <provider> for diagnostic output.

Missed secrets in recent commits: Confirm webhook delivery is active with secrets-scan webhooks status <repo>. Re-register webhooks if your Git provider rotated signing secrets.

High false-positive rate: Use secrets-scan pattern exclude <pattern_id> to suppress known-safe matches. Review custom patterns with pattern test before deploying.

Auto-revocation not triggering: Verify write-scope credentials are configured and the provider is enabled for the repo. Check revocation history for permission errors or rate-limit responses.

Deep scan timing out: Large monorepos may exceed default timeouts. Increase with --scan-timeout 1800 or split into sub-path scans using --path-filter src/.
